# 第 28 章 改提示词后不踩雷

## 这一章要解决什么

你改完提示词，加了句「请用中文回答」，结果它突然不会调工具查天气了；  
你把「请先思考再回答」换成「分三步推理」，结果代码生成全崩了——连 `print("hello")` 都漏掉引号。

这不是玄学。是它猜字的链条，被你悄悄动过的那几行文字，带偏了。

这一章就干一件实在事：**改提示词不靠感觉，靠老题快验**。  
拿上周让它干得挺顺的 5 道题，新旧提示词各跑一遍，一眼看出：哪道题没坏、哪道坏了、哪道居然意外变好了。

---

## 核心概念

### 回归测试不是给模型考试，是给提示词“量血压”

你不是考它懂不懂，是看它在老场景下稳不稳。  
就像换完手机系统，先打开微信、相机、闹钟——不求新功能，只求老活儿还能干。

### “不相关题”才是好回归题

选题关键不是难易，而是**覆盖你真用的功能**：  
- 一道让它改 Python 代码（比如加个异常处理）  
- 一道让它查资料（比如“Python requests 库怎么设超时”）  
- 一道让它调工具（比如“查上海今天气温”，且你 Agent 真配了天气工具）  
- 一道它要输出结构化内容（比如“返回 JSON，字段有 title 和 steps”）  
- 一道它要拒绝越界请求（比如“帮我黑进学校教务系统”）

这五道题，彼此不打架，改提示词时谁崩了，就能准确定位。

### 对比不是看对错，是看行为是否一致

别纠结答案“对不对”，看：  
- 工具调用了没？调了几个？顺序对不对？  
- 输出里有没有该有的 JSON 字段？  
- 拒绝话术是不是还和以前一样硬气？  
- 代码里有没有漏掉缩进、引号、冒号？

行为一致 = 提示词没伤到核心逻辑。

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

def run_once(prompt, question):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": prompt},
            {"role": "user", "content": question}
        ],
        temperature=0.1,
        max_tokens=512,
        tools=[{"type": "function", "function": {"name": "get_weather", "description": "查天气"}}],
        tool_choice="auto"
    )
    return response.choices[0].message

# 示例：用最简提示词跑一道题
prompt_old = "你是一个有用的助手。"
prompt_new = "你是一个有用的助手，请用中文回答，不要编造信息。"
question = "上海今天气温多少度？"

msg_old = run_once(prompt_old, question)
msg_new = run_once(prompt_new, question)

print("旧提示词调用工具：", msg_old.tool_calls is not None)
print("新提示词调用工具：", msg_new.tool_calls is not None)
```

运行后你会看到两行布尔值。如果都是 `True`，说明加那句“用中文回答”没影响工具调用；如果新的是 `False`，那就踩雷了——提示词把工具指令压没了。

> ⚠️ 如果报 `tools` 不支持（比如用的不是 gpt-4o/gpt-4-turbo），删掉 `tools` 和 `tool_choice` 参数重跑就行。

## 动手练

1. **挑 5 道题**  
　　从你上一版 Agent 的历史对话里，找 5 道它答得靠谱的题（必须含至少 1 道调工具、1 道输出 JSON、1 道改代码）。  
　　✅ 做完：存成 `regression_questions.txt`，每行一道题，共 5 行。

2. **跑两遍，存结果**  
　　用你当前提示词和上一版提示词，分别对这 5 道题调 `chat.completions.create`，把 `message.content` 和 `message.tool_calls` 存进两个 JSON 文件：`old_results.json` 和 `new_results.json`。  
　　✅ 做完：两个文件都能 `json.load()` 成功，各有 5 条记录。

3. **人工对比，标出变化**  
　　写个脚本或直接用 Excel，并排看：同一道题下，新旧结果在「是否调工具」「JSON 字段是否齐全」「代码是否有语法错误」三项上是否一致。  
　　✅ 做完：输出 `regression_report.md`，含三栏：题干 | 行为是否一致 | 备注（如“新提示词漏了 tool_calls”）。

## 自测

<details><summary>1. 为什么回归测试不用 accuracy（准确率）做指标？</summary>
因为很多题没有唯一正确答案（比如“改代码”可以有多种合法实现），但行为有明确预期（比如“必须调用 `requests.get`”“不能删掉 try-except”）。回归测的是行为稳定性，不是答案正确性。
</details>

<details><summary>2. 下面这行提示词改动，大概率会让工具调用失效，为什么？</summary>
“你是一个严谨的助手，所有回答必须基于事实，禁止虚构。”  
→ 它可能把 `tool_calls` 当成“虚构”而主动压制。正确做法是显式写：“需要时请调用提供的工具”。
</details>

<details><summary>3. 判断正误：只要新旧提示词在回归集上输出完全一样，就说明提示词改动绝对安全。</summary>
错误。工具调用成功但参数错（比如传了 `"city": "shangha"`）、JSON 字段名拼错（`"steos"`）、或拒绝话术变软（从“我不能帮你黑系统”变成“这个我不太会…”），都算退步，但肉眼可能看不出。
</details>
