# 第 24 章 哪些操作必须先问人再干

## 这一章要解决什么

你让模型帮你删测试库里的脏数据，它真去调 `DROP TABLE`；  
你让它给客户发个确认邮件，它顺手把「退款金额」改成 99999；  
你没拦它，它也没问你——等你发现时，钱转出去了，表删没了。

这不是它“坏”，是它根本分不清「改个 README」和「删生产数据库」谁更该打个问号。  
这一章就教你怎么给它装上刹车：**哪些动作必须踩住、弹窗、等你点“确定”才能动**。

---

## 核心概念

### 危险动作不是模型判断的，是你标出来的  
模型不会主动觉得“删库”危险。你得在工具定义里写清楚：  
```python
{"name": "delete_user_data", "is_dangerous": True, ...}
```  
它只认这个标记。不标？它就当是查天气。

### 拦住 ≠ 报错，而是暂停 + 返回待办清单  
拦住不是 throw exception 让整个流程崩掉。  
是让它停在那一步，把「谁要删谁的数据」「删哪几张表」「你点这里审批」打包成结构化结果，交给你处理。

### 审批通过后，得能续跑，不是重头来  
你点了“同意”，它不该再问一遍“要删吗？”，也不该从头思考“用户想干啥”。  
得记住刚才卡在哪、参数是什么，直接跳回那一步执行。

---

## 先跑起来

复制粘贴这段代码，确保已安装 `openai>=1.0`，密钥存在环境变量：

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

tools = [{
    "type": "function",
    "function": {
        "name": "delete_user_data",
        "description": "删除指定用户的全部数据（高危操作）",
        "parameters": {"type": "object", "properties": {"user_id": {"type": "string"}}},
        "is_dangerous": True  # ← 关键：你自己加的标记，模型看不见，但你的代码要看
    }
}]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "删掉用户 u789 的数据"}],
    tools=tools,
    tool_choice="auto"
)

# 看它选了哪个工具
if response.choices[0].message.tool_calls:
    call = response.choices[0].message.tool_calls[0]
    print("模型想调用：", call.function.name)
    print("参数：", call.function.arguments)
    # 输出会是：delete_user_data 和 {"user_id": "u789"}
```

跑完你会看到它确实选了 `delete_user_data`，还带对了参数。  
但注意：**这步还没真删**。这只是模型“说它想删”，你接下来要检查 `is_dangerous`，决定拦不拦。

---

## 动手练

1. **加标记**：在 `tools` 列表里，给 `delete_user_data` 工具加上 `"is_dangerous": True` 字段（上面代码里已有，确认它存在）。  
   ✅ 做完：运行代码，`print(call.function.name)` 输出仍是 `delete_user_data`，没报错。

2. **加拦截逻辑**：在 `response` 后面加几行，检查 `call.function.name` 对应的工具有没有 `"is_dangerous": True`；如果有，不执行，而是打印 `"需人工审批：删除用户 u789 数据"`。  
   ✅ 做完：输出里不再出现实际执行日志，只有一句审批提示。

3. **模拟审批通过**：写一个函数 `resume_after_approval(tool_call)`，输入就是刚才那个 `tool_calls[0]`，它直接调用 `json.loads(...)` 解析参数，然后打印 `"已执行：删除用户 u789 数据"`。  
   ✅ 做完：手动调用 `resume_after_approval(call)`，终端输出那句“已执行”。

## 自测

1. 如果我把 `is_dangerous` 写成 `"is_dangerous": "true"`（字符串），我的拦截逻辑还会生效吗？  
<details><summary>参考答案</summary>
不会。Python 里 `"true" != True`，`if tool.get("is_dangerous")` 会当成 `True`（非空字符串为真），但语义错了。应该严格用布尔值 `True`。
</details>

2. 模型返回了两个 tool_calls，第一个危险，第二个安全。我只检查第一个就拦住，是否合理？  
<details><summary>参考答案</summary>
不合理。必须遍历全部 tool_calls，只要有一个 is_dangerous=True，就要整体暂停。否则可能漏掉高危动作。
</details>

3. 为什么不能让模型自己判断“这个操作危不危险”，而必须由开发者硬编码 `is_dangerous`？  
<details><summary>参考答案</summary>
因为模型没有权限上下文（比如不知道这是生产库还是测试库）、没有后果感知（删1条vs删100万条）、且会幻觉。只有开发者清楚接口的真实影响，标记必须由人定。
</details>
