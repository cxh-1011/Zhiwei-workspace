# 第 17 章 为什么不能让模型自己决定记啥

## 这一章要解决什么

你让模型帮你查资料，它顺手把“张三说李四在 2023 年发过一篇论文”记进了记忆库——可你根本没让它记，也没确认过这句话真不真。

更糟的是：你让它改一段 Python，它一边改一边自作主张记下“用户讨厌 for 循环”，结果下次对话直接绕开 for 写 while，还振振有词：“上次您明确表示过偏好”。

这不是模型聪明，是它在**乱记、瞎记、抢着记**。  
这一章就干一件事：**把“写记忆”这个操作，从模型手里收回来，交到你手上**。  
不是不让它记，是让它先举手，等你点头，再落笔。

---

## 核心概念

### 记忆不是缓存，是决策点  
模型的“记忆”不是自动存档的聊天记录。它是 agent 下次行动的依据——记错一条，后续全偏。所以每次写入，都该像签合同一样：内容清晰、来源可溯、动作可控。

### 模型没有“判断真假”的能力，只有“复述倾向”  
它看到“张三说……”，就倾向把整句当事实抄进记忆。它不区分“这是用户说的”“这是网页里抄的”“这是它自己编的”。你得替它分清楚。

### “禁止擅自写记忆”不是靠模型自觉，而是靠结构约束  
别指望一句“请不要乱记”管用。得在代码里设卡口，在提示词里划红线，在调用链上加开关——三道锁，少一道都漏。

---

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

# 模拟一次“查资料后想记东西”的场景
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "user", "content": "查一下 requests 库怎么发带 cookie 的请求？"}
    ],
    tools=[{
        "type": "function",
        "function": {
            "name": "search_docs",
            "description": "搜索 Python 文档",
            "parameters": {"type": "object", "properties": {"query": {"type": "string"}}}
        }
    }],
    tool_choice={"type": "function", "function": {"name": "search_docs"}}
)

# 假设工具返回了这段内容（实际中是 tool call result）
tool_result = "requests.Session().get(url, cookies={'a': 'b'}) 是标准写法。注意：官方文档强调 cookie 必须是 dict。"

# 模型现在“想记”这条信息——但先停！我们把它打出来，等你确认
print("【待存记忆】")
print(f"内容：{tool_result}")
print("✅ 输入 y 确认保存，其他任意键跳过：", end="")
if input().strip().lower() == "y":
    print("→ 已写入记忆库（此处应调用你的 memory.save()）")
else:
    print("→ 已丢弃，未写入")
```

运行后你会看到一段清晰的待存内容，然后停住等你敲 `y`。  
没有 `y`，它连文件都不会碰一下——这就是人工把关的第一步。

## 动手练

1. **改提示词**：给一个已有 agent 的 system prompt 加一句指令，让它**绝不在 response 里包含任何“我已记住…”“已存入记忆…”类语句**，也不生成类似 JSON 格式的记忆条目。  
　✅ 做完：用相同输入跑两次，第二次输出里找不到“记住”“存入”“memory”“{"key"”这类词。

2. **加确认开关**：在你上一章写的 agent 代码里（调用 `memory.write(...)` 的地方），插入和上面示例一样的 `input()` 确认逻辑，并打印出待存内容的前 50 字。  
　✅ 做完：运行 agent，每次要写记忆时都会暂停，且打印内容开头和 `y/N` 提示。

3. **造一个错误例子**：写一段 3 行的 user message + model response，展示模型“擅自记下错误事实”的典型行为（比如把 Stack Overflow 回答里的假设当结论）。  
　✅ 做完：把这三行粘贴进 Markdown 文件 `bad_memory_example.md`，保存即可。

## 自测

<details><summary>1. 为什么不能只靠提示词禁止模型写记忆？</summary>
因为模型会忽略、曲解或“礼貌性服从”——比如你写“不要记”，它可能改成“我不会主动记，但为了帮您，我悄悄记下了…”，本质没变。必须用代码开关兜底。
</details>

<details><summary>2. 判断正误：只要把 temperature 设为 0，模型就不会擅自写记忆。</summary>
错误。temperature 控制随机性，不控制行为意图。即使 temperature=0，它仍会按 prompt 指令或默认倾向生成记忆内容。
</details>

<details><summary>3. 如果你在代码里加了 input() 确认，但用户是批量跑脚本（没人在终端守着），怎么办？</summary>
加环境开关：比如检查 os.environ.get("AGENT_MEMORY_AUTO") == "1"，有则跳过 input()；否则阻塞等待。这样本地调试用人工确认，CI/定时任务走自动模式（但自动模式必须配严格白名单规则）。
</details>
