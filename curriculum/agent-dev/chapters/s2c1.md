# 第 4 章 四段式写提示词

## 这一章要解决什么

你写：“帮我把这段 Python 代码改成用 pandas 读 Excel，加个错误处理。”

它真给你改了——但可能没加 try/except，或者把 `pd.read_excel()` 写成 `pd.read_xls()`，甚至顺手把你原来的注释全删了。

你再补一句：“别删注释，要用 try-except，文件路径是变量 `file_path`”，它又改一遍……结果注释回来了，但 `file_path` 又被硬写成 `"data.xlsx"`。

这不是它懒，是你没给它“上岗说明书”。

这一章就教你怎么写这份说明书：**角色、任务、约束、输出格式——四段，缺一不可，顺序不能乱**。  
不是为了显得专业，是让它少猜、少编、少自作聪明。

---

## 核心概念

### 角色：先告诉它“你是谁”，它才敢按身份做事  
不写角色？它默认自己是“万能答题机”——啥都敢答，啥都敢改。  
写“你是一个有十年 Python 经验的代码审查员”，它立刻收起瞎编函数名的劲儿，改代码前会先看上下文有没有 import pandas。

### 任务：只说“要做什么”，不说“怎么做”  
写“用 pandas 读 Excel”是任务；写“先 import pandas as pd，再调 pd.read_excel(file_path)”就是越界——那是你该干的活。  
模型不执行代码，它只生成文本。你塞太多步骤进去，它反而会漏掉真正的目标。

### 约束：挡住它最想乱来的那些地方  
比如“不许删原有注释”“不许改函数签名”“只改三行以内”——这些不是补充说明，是安全带。  
没有约束，它优化着优化着就把你的 `def calc(a, b):` 改成 `def calculate_numbers(x: int, y: int) -> float:`。

### 输出格式：让它交卷时“按格子填”  
写“返回纯 Python 代码，不要解释，不要 markdown”比“直接给我代码”管用十倍。  
它真会照做：你让加 ```python 就加，你让不加就真不加，连空行都跟你对齐。

## 先跑起来

复制粘贴这段代码，确保已设 `OPENAI_API_KEY` 环境变量：

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

prompt = """你是一个谨慎的 Python 代码迁移助手。
任务：把用户给的代码片段改成用 pandas 读取 Excel 文件，并加入基础错误处理。
约束：1. 不删除任何原有注释；2. 不修改函数名和参数名；3. 只添加/修改必要行，其余保持原样。
输出格式：只返回可直接运行的 Python 代码，不要解释，不要 markdown，不要空行。

原始代码：
def load_data():
    # 读取 CSV 文件
    with open("data.csv") as f:
        return f.read()
"""

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.2,
    max_tokens=300
)
print(response.choices[0].message.content)
```

你会看到一段干净的、带 try/except 的 pandas 代码，注释还在，函数名没变，也没多出一句废话。  
如果报错 `model not found`，把 `gpt-4o` 换成你账号能用的模型（比如 `gpt-3.5-turbo`）。

## 动手练

1. **改写需求**：把这句话拆成四段式提示词——  
   “帮我查下 requests 库怎么发带 cookie 的 POST 请求，给个例子。”  
   ✅ 做完：输出完整提示词文本，含明确的「角色」「任务」「约束」「输出格式」四部分，每段开头标好标题。

2. **找缺失项**：分析下面提示词缺哪一段——  
   “你很懂前端。把这段 HTML 加个深色模式切换按钮，用原生 JS 实现。只返回 HTML+JS 代码。”  
   ✅ 做完：指出缺失的段落（如“约束”），并补上一条具体约束（例如“不引入外部 CSS 或 CDN”）。

3. **查矛盾点**：下面提示词里有逻辑冲突——  
   “你是一个 Linux 系统管理员。任务：帮用户写一个备份脚本。约束：必须用 rsync，且不能用 sudo。输出格式：返回完整可执行 bash 脚本。”  
   ✅ 做完：指出哪两处约束打架（比如 rsync 同步系统目录通常要 sudo），并改写其中一条约束使其合理。

## 自测

<details><summary>1. 如果提示词写了“你是一个资深产品经理”，但任务却是“把这段 SQL 改成 pandas 代码”，会发生什么？</summary>
模型会优先扮演“产品经理”——可能加一堆需求分析、用户故事，而不是专注改代码。角色和任务不匹配，它会按角色脑补任务。
</details>

<details><summary>2. 判断正误：输出格式写成“用中文解释清楚”和“只返回代码”不冲突。</summary>
错误。二者直接冲突。“解释清楚”需要自然语言，“只返回代码”禁止自然语言。模型会选一个执行，大概率忽略后者。
</details>

<details><summary>3. 为什么“约束”不能写成“尽量不要删注释”？</summary>
“尽量”是模糊指令，模型没有“尽量”的执行标准。它要么删，要么不删——必须写成“不许删任何原有注释”这种无歧义禁令。
</details>
