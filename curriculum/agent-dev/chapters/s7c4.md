# 第 25 章 出问题了怎么查哪一步挂了

## 这一章要解决什么

你写了个 Agent，让它「查 Python 的 `requests.get()` 超时参数怎么设，然后改掉我本地 `fetch_data.py` 里的调用」。

它跑了一半卡住，最后返回「操作失败」——但没说哪步挂了。  
重跑？又得等 15 秒，还可能结果不一样。  
看日志？全是 `INFO:root:Calling model...`，看不出是工具调用超时了，还是模型根本没生成 tool call，还是文件读错了。

这一章就干一件事：**让每次失败都可回放**。  
不是靠猜，是靠 trace_id 找到那一趟完整流水；  
不是翻代码，是看日志就知道：第 3 步调 `read_file` 返回了空字符串，第 5 步 `write_file` 因为输入为空直接跳过。

## 核心概念

### 1. trace_id 是这次任务的身份证  
没有它，所有日志都是散装的。加一个 `uuid4()`，从最外层 `run_agent()` 开始传下去，每一步日志都带上。挂了？搜这个 ID 就行。

### 2. 每一步必须记四件事：工具名、输入、耗时、状态  
不是“调用了 tools”，而是 `"tool": "read_file", "input": {"path": "fetch_data.py"}, "duration_ms": 127, "status": "success"`。  
状态只分三类：`success` / `error` / `skipped`（比如模型没生成 tool call，这步就 skipped）。

### 3. 日志必须结构化，别打成字符串  
别写 `logger.info(f"call {tool} with {input} took {t}s")`。  
用 `logger.info("step", extra={"trace_id": ..., "tool": ..., "input": ..., "duration_ms": ...})`，后续能直接导出 JSON 查。

## 先跑起来

```python
import os
import time
import uuid
import logging
from openai import OpenAI

logging.basicConfig(level=logging.INFO, format='%(asctime)s %(levelname)s [%(trace_id)s] %(message)s')
logger = logging.getLogger(__name__)

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

def run_step(tool_name: str, input_dict: dict) -> dict:
    start = time.time()
    trace_id = input_dict.get("trace_id", str(uuid.uuid4()))
    
    try:
        # 模拟一个真实工具：读文件（这里故意让它在特定输入下失败）
        if tool_name == "read_file" and input_dict.get("path") == "fetch_data.py":
            result = "import requests\nrequests.get(url, timeout=5)"  # 成功
        elif tool_name == "read_file" and input_dict.get("path") == "broken.py":
            raise FileNotFoundError("No such file")
        else:
            result = {"ok": True}
        
        duration_ms = int((time.time() - start) * 1000)
        logger.info("step", extra={
            "trace_id": trace_id,
            "tool": tool_name,
            "input": input_dict,
            "duration_ms": duration_ms,
            "status": "success",
            "result_preview": repr(result)[:50]
        })
        return {"status": "success", "result": result}
    
    except Exception as e:
        duration_ms = int((time.time() - start) * 1000)
        logger.info("step", extra={
            "trace_id": trace_id,
            "tool": tool_name,
            "input": input_dict,
            "duration_ms": duration_ms,
            "status": "error",
            "error": str(e)
        })
        return {"status": "error", "error": str(e)}

# 运行一次失败任务
run_step("read_file", {"path": "broken.py", "trace_id": "test-123"})
```

你会看到一行日志，类似：  
`2024-05-20 14:22:33,456 INFO [test-123] step`  
后面跟着一大段 JSON 字段（取决于你的日志处理器）。关键是你能看到 `status: "error"` 和 `error: "No such file"`，且 trace_id 对得上。

## 动手练

1. **改日志格式，输出为 JSON 行**  
   把 `basicConfig` 改成用 `jsonlogger`（`pip install python-json-logger`），让每条日志是一行合法 JSON。  
   ✅ 做完：运行后 `grep test-123 *.log` 输出是纯 JSON，能被 `jq` 直接解析。

2. **给 `run_step` 加个 `timeout_sec=5` 参数，超时就标 `status: "error"` 并记录 `"timeout": true`**  
   用 `threading.Timer` 或 `signal.alarm`（Linux/macOS）实现。  
   ✅ 做完：调用 `run_step("read_file", {"path": "slow.py"}, timeout_sec=0.1)` 后日志里有 `"timeout": true`。

3. **写一个 `replay_trace(trace_id: str, log_file: str)` 函数，从日志文件里提取该 trace_id 的所有步骤，按时间排序打印**  
   ✅ 做完：对 `test-123` 调用后，`replay_trace("test-123", "app.log")` 输出两行：`[0ms] read_file → error: No such file`。

## 自测

<details><summary>1. 如果没传 trace_id，`run_step` 会生成新 ID。那两次调用传同一个 trace_id，日志里会混在一起吗？</summary>
会。trace_id 只是日志字段，不控制执行逻辑。如果两个并发任务用了同一个 trace_id，它们的日志会共享一个 ID，查的时候分不清谁是谁。正确做法是每个顶层任务生成唯一 ID，并确保子步骤继承它。
</details>

<details><summary>2. 下面这行日志字段是否符合本章要求？为什么？<br>`{"tool": "search_web", "input": "how to use requests timeout", "duration_ms": 2300, "status": "success"}`</summary>
不符合。缺 `trace_id`。没有 trace_id 就无法关联上下文，这条日志单独存在毫无排查价值。
</details>

<details><summary>3. 为什么不用 print 而要用 structured logging？举一个 print 解决不了、structured logging 能解决的具体场景。</summary>
比如要查「所有耗时超过 2s 的 `write_file` 调用」。print 输出是文本，得用正则匹配+字符串切片；structured logging 输出是 JSON，一行 `jq 'select(.tool=="write_file" and .duration_ms > 2000)' app.log` 就拿到全部。
</details>
