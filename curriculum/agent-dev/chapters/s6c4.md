# 第 21 章 RAG 为啥胡说八道还理直气壮

## 这一章要解决什么

你让模型查资料：“Python 怎么用 `concurrent.futures` 跑带返回值的线程？”  
你喂给它三段文档：一段讲 `ThreadPoolExecutor.submit()`，一段讲 `as_completed()`，一段讲 `map()`。  
它张嘴就答：“用 `executor.run_async()`，传入 `return_values=True` 参数……”

——这函数根本不存在，参数也是瞎编的，但它说得比真的一样。

这就是 RAG 最扎心的翻车现场：**检索对了，生成胡扯，还理直气壮**。  
不是它懒，是它根本没“看”你给的材料；不是它坏，是它被训练成“必须答”，而不是“答不出就闭嘴”。

这一章不教你调向量库、不教 chunk 策略。就干一件小事：**揪住它的嘴，问它：这句话，到底抄没抄检索结果？**

---

## 核心概念

### 它不“读”，它“拼”
模型不会通读你给的三段检索文本，再总结。它只是把问题 + 检索文本一起塞进上下文，然后——**接着这个长字符串，往下猜字**。  
所以如果检索段落里没写 `run_async()`，它凭空造出来，完全不违和。它不是在“编”，是在“猜”。

### “自信”是错觉，是 logprobs 高
你看到它斩钉截铁说“必须加 `return_values=True`”，不是因为它有把握，而是 token `True` 在它当前预测里概率特别高（logprobs 接近 0）。  
而 `return_values=` 这个前缀，在训练数据里高频出现，它顺手就接上了——跟检索内容无关。

### “不知道”不是默认选项
模型在预训练时，几乎没见过“我不知道”这种回答。它见过的是“根据文档…”，“官方推荐…”，“可以使用…”。  
所以你没明说“不准编”，它就默认：**宁可错，不能空**。

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

# 模拟一次 RAG 的输入：问题 + 检索到的两段文本
retrieved = [
    "ThreadPoolExecutor.submit() 提交单个任务，返回 Future 对象。",
    "as_completed() 按完成顺序返回 Future 结果，适合处理多个异步任务。"
]
question = "怎么拿到线程执行后的返回值？"

prompt = f"""你是一个 Python 助手。只根据以下资料回答问题，资料外的内容一律不提。
如果资料里没有明确答案，就回答“资料未说明”。

资料：
{chr(10).join(retrieved)}

问题：{question}
回答："""

resp = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.0,
    max_tokens=128,
    logprobs=True,
    top_logprobs=1
)

answer = resp.choices[0].message.content.strip()
print("RAG 回答：", answer)
# 你会看到类似：“调用 submit() 返回 Future，再用 result() 方法获取返回值。”
# ——这句话里，“result()” 在检索文本里没出现过，就是它自己加的。
```

## 动手练

1. **照抄检查**：用上面代码，把 `retrieved` 改成只留第一句 `"ThreadPoolExecutor.submit() 提交单个任务，返回 Future 对象。"`，运行。  
　→ 输出中找有没有出现 `result()` 或 `future.result()` 字样。有，就说明它编了。

2. **标出编造部分**：把 `question` 改成“`as_completed()` 怎么用？”，`retrieved` 只留第二句。运行后，把回答逐词对照第二句原文，标出第一个不在原文里出现的动词（比如“遍历”“迭代”“yield”等）。

3. **改提示词治乱编**：在 `prompt` 开头加一句：“**严禁使用任何资料中未出现的函数名、参数名、方法名。若不确定，必须回答‘资料未说明’。**” 再跑一次，确认回答变成“资料未说明”或严格复述原文片段。

## 自测

<details><summary>1. 如果把 temperature 设为 1.0，RAG 回答更可能编还是更可能守规矩？</summary>
更可能编。temperature 高 → 预测更随机 → 更敢从训练记忆里捞词，而不是死抠检索文本。
</details>

<details><summary>2. 下面这段提示词能防止乱编吗？为什么？  
“请基于资料回答，不要胡说。”</summary>
不能。太模糊。“胡说”没定义，模型不知道哪个词算胡说。必须指明禁止行为（如“禁用未出现的函数名”）和兜底动作（如“答‘资料未说明’”）。
</details>

<details><summary>3. 假设检索段落里写了 “`future.result()` 获取结果”，但没写 “`.result()` 是方法调用”，RAG 回答 “调用 `.result()` 方法”，这句话算照抄吗？</summary>
不算照抄。“`.result()`” 是原文出现的字符串，直接复用；“方法”是通用名词，属于合理衔接，不算新增事实。判断标准是：**关键名词/符号是否原样出现**。
</details>
