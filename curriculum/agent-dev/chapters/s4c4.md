# 第 14 章 一次运行全过程图解

## 这一章要解决什么

你写好一段提示词，`openai.chat.completions.create(...)` 一跑，答案就出来了。

但中间发生了啥？  
它真“想”了？还是只在抄？  
工具调没调成？失败了谁负责重试？  
它说“我查完了”，你咋知道它没瞎编？

这一章不讲大道理。我们**把一次运行拆成帧**：  
输入进来 → 模型吐出思考文字 → 看到 `{"name": "search"}` 就去调函数 → 函数返回空字符串 → 它又生成下一轮 → 最后输出 `{"final_answer": ...}`  

你看得见每一步的输入和输出，才敢改、敢调、敢修。

---

## 核心概念

### 1. Agent 不是新模型，是“人+模型+工具”的流水线  
它自己不会查天气，也不会改代码。它只是**读你给的提示词 + 上一轮结果，然后决定下一步干啥**——要么继续生成文字，要么填个 tool call，要么直接交答案。  
没有 magic，只有 if/else 和 prompt 工程。

### 2. “思考”不是内部状态，是明文输出的 token  
模型没有“脑内草稿”。它的“思考过程”，就是你看到的那几行文字：  
```
让我先查一下 Python 的 requests 库文档……  
调用 get_docs(tool_name="requests", version="2.31")  
```  
这些字，和最终答案一样，都是它一个字一个字猜出来的。  
你加 `logprobs=True`，还能看见它猜每个字时有多犹豫。

### 3. 工具调用不是自动发生的，是模型“写出来”的指令  
模型不会主动联网。它只是按你给的 `tools` 定义，**生成符合 JSON Schema 的字符串**（比如 `{"name": "web_search", "arguments": "{\"q\": \"Agent 开发 教程\"}"}`）。  
你的代码拿到这个字符串，解析、调函数、塞回 `tool_calls` → 才算真正调了一次工具。

---

## 先跑起来

复制这段代码，保存为 `trace_run.py`，运行：

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

messages = [{"role": "user", "content": "把这段代码改成用 requests.post 发送 JSON：import urllib.request; urllib.request.urlopen('http://a.b/c')"}]
tools = [{
    "type": "function",
    "function": {
        "name": "code_convert",
        "description": "把旧代码转成 requests.post 形式",
        "parameters": {"type": "object", "properties": {"old_code": {"type": "string"}}, "required": ["old_code"]}
    }
}]

res = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=tools,
    tool_choice="auto",
    max_tokens=512
)

print("→ 模型第一轮输出：")
print(res.choices[0].message.content or "(空)")
print("\n→ 它选择调用工具：")
if res.choices[0].message.tool_calls:
    tc = res.choices[0].message.tool_calls[0]
    print(f"  name: {tc.function.name}")
    print(f"  args: {tc.function.arguments}")
```

你会看到类似这样的输出：  
→ 模型第一轮输出：  
`我需要把 urllib.request 调用换成 requests.post……`  
→ 它选择调用工具：  
`name: code_convert`  
`args: {"old_code": "import urllib.request; urllib.request.urlopen('http://a.b/c')"}`
  
说明：它没直接回答，而是**先写了思考文字，再生成 tool_call**。这就是 Agent 的第一步。

## 动手练

1. **加日志**：在上面代码里，`res = ...` 前后各加一行 `print("【开始请求】")` 和 `print("【收到响应】")`。运行，确认你能对上“思考文字”和“tool_call”出现在哪两行之间。  
✅ 做完标志：你能在终端里清晰指出哪行是请求发出、哪行是思考、哪行是工具名、哪行是参数。

2. **手动模拟失败**：把 `tools` 列表清空（`tools=[]`），再跑一次。观察 `res.choices[0].message.content` 是否变成直接改代码的答案（而不是 tool_call）。  
✅ 做完标志：你看到 content 里出现了 `import requests; requests.post(...)` 这样的真实代码。

3. **还原完整链路**：用 `messages` 加一条历史记录：  
```python
messages = [
    {"role": "user", "content": "帮我查下今天北京天气"},
    {"role": "assistant", "tool_calls": [{"id": "call_1", "type": "function", "function": {"name": "get_weather", "arguments": '{"city": "北京"}'}}]},
    {"role": "tool", "tool_call_id": "call_1", "content": ""}  # 模拟工具返回空
]
```  
再跑，看它第二轮 `content` 写了什么。  
✅ 做完标志：你截到的输出里有类似“工具没返回结果，我再试一次……”或直接放弃的句子。

## 自测

<details><summary>1. 如果把 `tool_choice="required"`，模型还会输出 `content` 吗？</summary>
不会。它必须生成至少一个 `tool_calls`，`content` 字段会是 `None` 或空字符串。
</details>

<details><summary>2. `tool_calls` 是模型“调用”了函数，还是只是“说它要调”？</summary>
只是“说它要调”。真正的函数调用是你写的代码解析 `tool_calls` 后手动执行的。模型连 import 都做不到。
</details>

<details><summary>3. 为什么 `messages` 里要有 `"role": "tool"` 这种角色？不加行不行？</summary>
不行。这是告诉模型：“刚才你让工具干的事，结果是这个（空/报错/成功）”。不加，它就不知道工具返回了啥，可能瞎猜、死循环，或直接交错误答案。
</details>
