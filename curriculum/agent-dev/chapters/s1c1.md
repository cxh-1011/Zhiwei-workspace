# 第 1 章 模型其实只会猜下一个字

## 这一章要解决什么

你让它改一段代码，它改得能跑；你问它原理，它讲得头头是道。很容易觉得它"懂了"。

这一章要把这个错觉拆掉。它每一次只做一件事：**看上文，猜下一个字**。猜完接上去，再猜下一个。

把这件小事想透，后面所有事都顺了——为什么提示词换个说法效果差很多，为什么它会把不存在的函数名编得像真的，为什么聊久了它会忘事。

## 核心概念

### 1. 它看不见"字"，只看见编号

模型不认识汉字，也不认识英文单词。你说的话会先被切成一小块一小块，叫 token，每块换成一个整数编号，模型只处理这串整数。

中文一个字通常就是一个 token，英文常见词是一个 token，生僻词会被切成两三块。所以"同样一句话"在不同语言里占的 token 数可能差一倍——这直接决定你花多少钱、能聊多久。

### 2. 每一步只算一件事：下一个 token 是谁

给它一段上文，它输出的是**词表里每个 token 排在下一位的概率**。词表通常十万个左右，所以它内部吐出的是一个十万维的分数表。

这里有个容易讲错的地方，值得单独记住：

- **算出这张分数表**：确定的过程。同样的输入、同样的模型，分数一样。
- **从分数表里挑一个**：这才是采样。temperature 就是拧这个旋钮——调到 0 基本总挑最高分的那个，调高就更容易挑到次高、第三高。

所以"temperature=0 就一定可复现"也不完全对：浮点运算顺序、批处理、有些模型内部的路由，都可能让两次结果差一点点。

### 3. 生成是一层层接上去的

它不会"先想好整段话再写出来"。写完第一个 token，把这个 token 接到上文末尾，重新算一遍，再挑第二个。如此循环。

这就是为什么它会前后矛盾——写到第 200 个字的时候，它并没有在做"全局检查"，它只是在接着上文往下猜。也是为什么你让它"先列提纲再写"，效果会明显变好：提纲进了上文，后面每一步都能看到它。

## 先跑起来

第一段：看一句话到底被切成了几块。

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")   # GPT-3.5/4 用的那套
text = "今天天气不错"
ids = enc.encode(text)
print(ids)                                    # 一串整数
print(len(ids), "个 token")

# 每个 token 单独还原成文字
for i in ids:
    print(i, "->", enc.decode_single_token_bytes(i).decode("utf-8", "replace"))
```

注意两点：一是 `tiktoken` 第一次用会联网下载词表，断网会报错；二是单个 token 不一定能解码成完整汉字，所以要带 `"replace"` 兜底——这也是为什么切 token 的边界和"字"的边界不是一回事。

第二段：看它给下一个 token 排的名次。

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],
    base_url=os.environ.get("OPENAI_BASE_URL"),   # 用国内模型时换成对应地址
)

resp = client.chat.completions.create(
    model=os.environ.get("OPENAI_MODEL", "gpt-4o-mini"),
    messages=[{"role": "user", "content": "今天天气"}],
    max_tokens=1,
    temperature=0,
    logprobs=True,
    top_logprobs=5,          # 要前五名
)

top = resp.choices[0].logprobs.content[0].top_logprobs
for item in top:
    print(round(2.718281828 ** item.logprob, 3), repr(item.token))
```

看到的就是"它认为下一个字可能是哪五个、各有多大把握"。

如果你用的接口不返回 `logprobs`（不少国产模型接口不支持），这段会直接报错。那就跳过它，改用第一段代码观察切分——本章的重点在概念，不在这个接口。

## 动手练

**1. 数一数你的名字占几个 token**

做什么：用 `tiktoken` 分别编码你的中文名、拼音、和一个英文单词。
怎么算做完了：打印出三组 token 数量，并写一行结论：中文字符数和 token 数的比例大概是多少。

**2. 中英文差多少**

做什么：准备同一段意思的中文和英文各一句（60 字左右），分别编码。
怎么算做完了：输出两个 token 数，并算出英文比中文省了还是多了百分之几。

**3. 让它栽一次**

做什么：给模型一个明显残缺的上文，比如"北京是中国的"，后面接一个强制转折的要求，看它会不会硬编。
怎么算做完了：贴出你的提问和它的回答，用一句话说明：它这次是靠上文猜的，还是真的知道。

## 自测

**1.** 两个不同的汉字，在同一个模型里会不会对应同一个 token 编号？

<details><summary>参考答案</summary>
不会。一个 token 编号唯一对应词表里的一块内容，两个不同的字是不同的 token。反过来不成立：一个常用词可能只占一个 token，而一个字也可能被切进两个 token 里。
</details>

**2.** 把 temperature 设成 0，同一个问题问两次，得到的回答一定一字不差吗？

<details><summary>参考答案</summary>
不一定。temperature=0 只是每一步都挑概率最高的那个 token，但分数本身可能因为浮点误差、批处理、服务端并发等因素有极小差异；两个 token 分数非常接近时，这点差异就足以让结果不同。
</details>

**3.** 为什么"先让它列提纲，再让它写正文"通常比"直接写正文"效果好？

<details><summary>参考答案</summary>
因为它每一步只能看到上文。提纲写进上文之后，后面每个 token 的预测都被提纲约束住了；不列提纲时，它只能顺着已写的句子往下猜，容易越写越偏。
</details>
