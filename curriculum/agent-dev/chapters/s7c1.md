# 第 22 章 让回答一出来就显示

## 这一章要解决什么

你让模型查个 API 文档，它卡住三秒，然后“唰”一下吐出 800 字——你刚想划重点，光标已经滚到底了。

你让它改一段报错的代码，它回你：“好的，我来帮你分析……（10 秒后）……综上，把 `range(5)` 改成 `range(6)` 就可以了。”  
——可你根本没等到“综上”，就以为它挂了，又点了一次发送。

这一章就干一件事：**不让用户盯着空白框发呆**。  
把那 800 字拆成一个个字、一个个词，来了就打，边生成边显示。  
不是等它“想完”，而是看它“正在想”。

---

## 核心概念

### 它不是一口气写完再交卷  
模型没有“草稿纸”。它每生成一个 token，就立刻发给你（如果你开了流式）。  
你看到的“完整回答”，其实是几百次“猜下一个字”的结果拼起来的。

### 流式（stream=True）不是锦上添花，是默认该开的开关  
不开 stream，你得等全部 token 生成完才拿到 response；  
开了 stream，你第一秒就能收到第一个 token，比如 `"{"` 或 `"我"` 或 `"```py"` ——  
哪怕后面还要等 5 秒，用户也知道自己没白等。

### token 不等于字，但你可以当字用  
英文里一个 token 可能是 `"ing"`，中文里大概率是一个字或一个词（比如 `"函数"` 算一个 token）。  
你不用数它，只要知道：**每次 `.delta.content` 里出来的，就是它刚猜出来的那一小块**。  
拼起来，就是最终答案。

---

## 先跑起来

复制粘贴这段代码，保存为 `stream_demo.py`，运行：

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "用 Python 写一个函数，输入数字 n，返回前 n 个斐波那契数"}],
    stream=True,
)

for chunk in stream:
    if chunk.choices[0].delta.content is not None:
        print(chunk.choices[0].delta.content, end="", flush=True)
print()  # 换行
```

你会看到：字符一个一个蹦出来，像打字机。  
可能开头是 `def`，接着是 ` fib`，再是 `(n):`……最后停在 `return` 结尾。  
如果某次 `chunk.choices[0].delta.content` 是 `None`，说明这包没新内容（比如只带 usage 或 finish_reason），跳过就行。

> 💡 提示：第一次跑慢？正常。模型启动+网络延迟，但后续每个 token 延迟通常 <200ms。

## 动手练

1. **改脚本，加计数器**  
   在 `print(...)` 前加一行：`print(f"[{len(chunk.choices[0].delta.content)}]", end="")`  
   ✅ 做完标志：输出里能看到类似 `[1][1][2][1][1]...`，每个方括号是当前 token 的字符长度（中文基本都是 1 或 2）

2. **让它“解释自己怎么想的”**  
   把 `messages` 换成：`[{"role": "user", "content": "请一边写斐波那契函数，一边说出你的思考步骤，每步用「→」开头"}]`  
   ✅ 做完标志：输出中出现多个 `→`，且它们和代码混在一起实时打出（不是先打完所有 `→` 再打代码）

3. **存成文件，逐行写入**  
   把 `print(...)` 换成：`with open("output.txt", "a", encoding="utf-8") as f: f.write(chunk.choices[0].delta.content)`  
   ✅ 做完标志：运行完后 `cat output.txt`（Mac/Linux）或 `type output.txt`（Windows）能看到和命令行一模一样的逐字输出

## 自测

1. 如果把 `stream=True` 改成 `stream=False`，代码会报错吗？为什么？  
<details><summary>参考答案</summary>
不会报错，但会直接抛出 `TypeError: 'ChatCompletion' object is not iterable`。因为非流式返回的是单个 ChatCompletion 对象，不能用 `for chunk in ...` 遍历。
</details>

2. 下面这段代码漏了什么关键判断，会导致崩溃？  
```python
for chunk in stream:
    print(chunk.choices[0].delta.content, end="")
```  
<details><summary>参考答案</summary>
没检查 `chunk.choices[0].delta.content` 是否为 None。当模型返回 finish_reason 或 usage 时，content 是 None，直接 print 会报错。
</details>

3. 为什么 `flush=True` 不能删？删了会怎样？  
<details><summary>参考答案</summary>
Python 默认行缓冲，不加 flush=True 时，print 的内容会卡在内存里等换行符或缓冲区满才输出。删掉后你会看到所有字符“突然一起出现”，失去流式效果。
</details>
