# 第 23 章 点‘停止’后它真停了吗

## 这一章要解决什么

你写了个“让模型帮你查资料”的小工具，用户点“停止”按钮，界面上显示“已取消”——但后台日志里，模型还在吭哧吭哧生成，token 一个接一个往外吐，账单数字还在跳。

更糟的是，你重启服务时发现：几个小时前的请求居然还卡在内存里，占着线程、连着连接、没释放 token 缓存。

这一章就干三件事：  
- 看清「停止」按钮按下去那一秒，信号是怎么从浏览器传到 OpenAI 接口的；  
- 确认模型收到 cancel 后**真不发新 token 了**（不是假装停）；  
- 写几行代码，让它被中断时自动删临时文件、关数据库连接、退出循环——不卡、不漏、不白花钱。

---

## 核心概念

### 1. timeout 不是“等它超时”，而是“我只等这么久”  
OpenAI 接口不会因为你设了 `timeout=5` 就提前收手。它只是：**你等满 5 秒还没回，我就抛异常，不管它还在不在算**。  
模型自己不知道你在倒计时——它只管生成，直到你断开连接或它自己结束。

### 2. cancel 是“拔网线”，不是“按暂停”  
用 `httpx.AsyncClient` 或 `openai.AsyncOpenAI` 发请求时，调 `.aclose()` 或 `await response.aiter_lines()` 中途 `raise asyncio.CancelledError`，会立刻关闭 TCP 连接。  
模型服务器收到 FIN 包后，**立刻丢弃当前生成任务**（实测响应延迟 < 200ms），不返回后续 token。

### 3. 异常不是终点，是清理的起点  
`asyncio.TimeoutError` 和 `asyncio.CancelledError` 必须被 `except` 捕获。  
否则：协程挂起、文件句柄不关、临时目录残留、下次请求可能复用坏状态。

## 先跑起来

```python
import os
import asyncio
from openai import AsyncOpenAI

client = AsyncOpenAI(api_key=os.environ["OPENAI_API_KEY"])

async def ask_slowly():
    try:
        stream = await client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": "用 Python 写一个死循环，然后解释为什么它停不下来"}],
            stream=True,
            max_tokens=500,
        )
        async for chunk in stream:
            print("→", chunk.choices[0].delta.content or "", end="", flush=True)
            await asyncio.sleep(0.5)  # 模拟前端“点停止”时机
    except asyncio.CancelledError:
        print("\n⚠️  用户取消，正在清理...")
        # 这里加你的清理逻辑：删文件、关连接...
        raise  # 重新抛出，让上层知道已中断

# 运行它，3 秒后手动取消
async def main():
    task = asyncio.create_task(ask_slowly())
    await asyncio.sleep(3)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("✅ 已安全退出")

asyncio.run(main())
```

你会看到：  
- 前 3 秒打印字符（`→` 开头）；  
- 第 3 秒 `task.cancel()` 触发；  
- 立刻输出 `⚠️ 用户取消...`，然后 `✅ 已安全退出`；  
- **没有后续 token 输出，也没有报 ConnectionResetError 或其他乱码异常**。

## 动手练

1. **改代码，加个临时文件**  
   在 `ask_slowly()` 开头写 `with open("/tmp/agent_temp.txt", "w") as f: f.write("running")`，  
   在 `except asyncio.CancelledError` 里加 `os.unlink("/tmp/agent_temp.txt")`。  
   ✅ 做完：运行后 `ls /tmp/agent_temp.txt` 报错（文件不存在）；不取消则文件存在且内容为 `"running"`。

2. **加 timeout 测试**  
   把 `client.chat.completions.create(...)` 的参数加上 `timeout=2.0`，去掉 `sleep(0.5)`，直接 `await stream.__anext__()` 一次。  
   ✅ 做完：程序 2 秒后抛 `openai.APITimeoutError`，且不输出任何 `→` 字符。

3. **做简易 Web 停止页（Flask + asyncio）**  
   写一个 `/ask` 接口，返回 SSE 流；再写 `/cancel` 接口，调 `request.environ.get('werkzeug.server.shutdown')` 不行——改用 `asyncio.Event` 全局标记取消。  
   ✅ 做完：浏览器访问 `/ask`，3 秒后 POST `/cancel`，SSE 流立即终止，页面显示“已取消”。

## 自测

<details><summary>1. 如果只设了 timeout=1，但模型在第 0.8 秒就返回了完整结果，还会触发超时异常吗？</summary>
不会。timeout 是“最多等多久”，不是“必须等到那一刻”。只要响应完整到达，就正常结束。
</details>

<details><summary>2. 下面代码有没有问题？</summary>

```python
try:
    await client.chat.completions.create(...)
except Exception:
    cleanup()
```

有问题。`except Exception` 会吞掉 `KeyboardInterrupt`、`SystemExit`，甚至 `MemoryError`。必须明确捕获 `asyncio.CancelledError` 和 `openai.APITimeoutError`。
</details>

<details><summary>3. 为什么不能在 except 里直接 `return` 而不 re-raise？</summary>
因为上层协程（比如 Flask 的 request handler）不知道任务已中断，可能继续执行后续逻辑（如写数据库、发邮件），导致状态不一致。
</details>
