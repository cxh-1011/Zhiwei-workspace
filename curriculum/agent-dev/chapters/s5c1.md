# 第 15 章 对话太长了，怎么砍才不丢重点

## 这一章要解决什么

你让模型帮你查资料，它先问“需要哪方面的资料？”，你回“Python 里怎么安全读取 YAML 文件”，它又问“用哪个库？PyYAML 还是 ruamel.yaml？”，你答“PyYAML”，它才开始写代码……  
最后你翻聊天记录，发现真正有用的就两行：你的问题 + 它给的代码。中间全是来回确认的废话。

对话长了，模型就容易漏重点、记混上下文、甚至把你自己删掉的旧方案又搬出来。  
这一章就干一件事：**从一堆字里，挑出真正干活的那几句话，其余全砍掉**。不是靠感觉，是靠规则——谁说的、什么时候说的、说了啥事。

---

## 核心概念

### 1. 对话不是流水账，是角色+动作+时间戳的组合  
模型不关心“你好呀”，但关心“用户说：把 config.yaml 里的 timeout 改成 30”。  
保留时只留三类句子：  
- 用户明确下达指令（含需求、修改、提问）  
- 模型给出可执行结果（代码、命令、结构化数据）  
- 双方确认关键决策（如“确定用 PyYAML”“不再重试”）

### 2. 时间顺序不能乱，但可以跳着留  
你先说“查下 API 文档”，它回“文档链接是…”，你再问“怎么加超时？”，它改代码——这三句必须按顺序留。  
但中间插的“好的！”“收到！”“稍等”全扔。

### 3. 删减不是压缩，是做减法选子集  
不用 summarize，不用 rephrase，不调大模型。  
就是遍历每一行，用 `if` 判断：是不是用户？是不是带动词/名词/数字的关键句？是不是和上一句有逻辑依赖？  
——像筛沙子，不是磨面粉。

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

# 模拟一段真实对话（你真会遇到的场景）
raw_msgs = [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！请问有什么可以帮您？"},
    {"role": "user", "content": "我有个 Python 脚本，想安全读取 YAML 配置文件"},
    {"role": "assistant", "content": "推荐用 PyYAML，并加 try-except。"},
    {"role": "user", "content": "能给个例子吗？"},
    {"role": "assistant", "content": "```python\nimport yaml\ntry:\n    with open('config.yaml') as f:\n        cfg = yaml.safe_load(f)\nexcept Exception as e:\n    print(f'加载失败: {e}')\n```"},
    {"role": "user", "content": "谢谢！"}
]

# 简单规则裁剪：只留 user 的非问候句 + assistant 的代码块或含 try/except 的句子
def trim_conversation(msgs):
    kept = []
    for m in msgs:
        if m["role"] == "user" and not any(kw in m["content"] for kw in ["你好", "谢谢", "hi", "bye"]):
            kept.append(m)
        elif m["role"] == "assistant" and ("```" in m["content"] or "try" in m["content"].lower()):
            kept.append(m)
    return kept

trimmed = trim_conversation(raw_msgs)
for i, m in enumerate(trimmed):
    print(f"[{i+1}] {m['role']}: {m['content'][:50]}...")
```

运行后你会看到：  
```
[1] user: 我有个 Python 脚本，想安全读取 YAML 配置文件...  
[2] assistant: 推荐用 PyYAML，并加 try-except。  
[3] user: 能给个例子吗？  
[4] assistant: ```python\nimport yaml\ntry:\n    with open('...
```

注意：第 2 条没代码但留了——因为它是关键决策句（定了技术选型）。这就是“规则”的意思：你定，它守。

## 动手练

1. **改规则，砍更狠**：把 `trim_conversation` 改成只留 `user` 的第一句需求 + `assistant` 的第一个代码块。运行后输出应只有 2 行。  
2. **加时间感知**：给每条消息加 `"timestamp": "2024-06-10T14:22:01"` 字段（模拟真实日志），改函数，确保即使对话被打断重连，也能按时间顺序保留最近 3 条关键句。  
3. **导出为文件**：把裁剪后的对话写入 `summary.md`，格式为：  
   ```md
   ## 用户需求  
   我有个 Python 脚本...  
   
   ## 模型方案  
   ```python  
   import yaml  
   ...  
   ```  
   ```  
   运行后检查文件内容是否符合格式。

## 自测

<details><summary>1. 如果把 `trim_conversation` 里的 `"try"` 改成 `"TRY"`（全大写），会发生什么？</summary>
什么也不会发生——因为 `m["content"].lower()` 已转小写，`"TRY"` 变成 `"try"`，判断依然成立。
</details>

<details><summary>2. 下面哪条消息该被保留？为什么？</summary>
`{"role": "user", "content": "等等，我刚发错了，用 ruamel.yaml"`  
该保留。它是对前序决策的主动修正，属于关键决策句（推翻旧方案，立新方案）。
</details>

<details><summary>3. 判断正误：用大模型 summarize 对话，比用规则裁剪更准确。</summary>
错误。大模型 summarize 可能编造不存在的结论、丢失原始约束条件（如“必须用 PyYAML”），而规则裁剪只做机械筛选，100% 可控、可复现、无幻觉。
</details>
