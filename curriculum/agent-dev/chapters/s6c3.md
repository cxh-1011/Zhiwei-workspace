# 第 20 章 召回太多？挑出前三名再细看

## 这一章要解决什么

你让模型帮你查资料，它调了向量库，唰一下捞出 10 个段落。  
你扫了一眼，前两段是讲猫的，中间三段在说火箭燃料，最后那个居然在聊咖啡因代谢……  

它没撒谎——确实都含“caffeine”这个词。但你真正想看的，就那两三段。  
这一章就干一件事：**别让模型直接瞎猜答案，先让它当个裁判，给召回结果打分、排序、砍到只剩前三**。

就像你搜完 GitHub，不会全点开看，而是先扫标题、看 star 数、瞄第一行代码——这章教你怎么让模型也这么干。

---

## 核心概念

### 为什么不能直接喂全部召回内容？

模型上下文有限。你塞 10 段、每段 500 字，光 token 就快爆了。更糟的是：噪声越多，正经信息越容易被淹没。它不是“读完再答”，是边读边猜——读到第 8 段时，早把第 1 段忘干净了。

### 为什么用小模型重打分，而不是大模型直接答？

大模型贵、慢、还爱编。你只是要个“相关性分数”，不是写论文。用一个轻量级模型（比如 `text-embedding-3-small`）算相似度，又快又稳，还不瞎发挥。

### 为什么只留 top3？不是 top5 或 top1？

因为下一章你要让 Agent 把这 3 段喂给大模型做精读。留太多，它会乱；留太少，可能漏关键信息。3 是实测下来最稳的起点——够用，不拖沓。

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

# 模拟召回的 10 段文字（实际来自向量库）
chunks = [
    "咖啡因在肝脏中主要由 CYP1A2 酶代谢。",
    "猫对咖啡因极度敏感，40mg/kg 可致死。",
    "SpaceX 星舰第三次试飞于 2024 年 3 月成功入轨。",
    "人体清除半杯咖啡中的咖啡因约需 5 小时。",
    "火箭燃料液氧沸点为 -183°C。",
    "咖啡因能阻断腺苷受体，从而提神醒脑。",
    "NASA 的 SLS 火箭使用 RS-25 主发动机。",
    "长期高剂量摄入咖啡因可能导致焦虑和失眠。",
    "咖啡因代谢速度受遗传因素影响很大。",
    "Falcon 9 第一级可重复使用最多 20 次。"
]

query = "咖啡因在人体内怎么被清除？"

# 用 embedding 算相似度（小模型，快）
query_emb = client.embeddings.create(
    input=query,
    model="text-embedding-3-small"
).data[0].embedding

chunk_embs = client.embeddings.create(
    input=chunks,
    model="text-embedding-3-small"
).data

# 简单点积算相似度（cosine 近似）
import numpy as np
scores = [float(np.dot(query_emb, emb.embedding)) for emb in chunk_embs]
ranked = sorted(zip(chunks, scores), key=lambda x: x[1], reverse=True)

print("重排后 top3：")
for i, (text, score) in enumerate(ranked[:3]):
    print(f"{i+1}. [{score:.2f}] {text}")
```

运行后你会看到：含“清除”“代谢”“半衰期”“肝脏”的几段排在前面，猫、火箭、Falcon 9 全被压到后面去了。  
注意：如果报错 `text-embedding-3-small` 不可用，换成 `text-embedding-3-large` 或 `text-embedding-ada-002`（改一行就行）。

## 动手练

1. **改输入**：把 `query` 换成 `"猫误食咖啡因会怎样？"`，跑一遍，确认前两条是讲猫的段落。  
   ✅ 做完标志：输出第一行是 `"猫对咖啡因极度敏感……"`，第二行是 `"咖啡因在肝脏中……"`（顺序可换，但这两条必须在 top2）

2. **加阈值过滤**：在排序后加一句 `ranked = [(t,s) for t,s in ranked if s > 0.6]`，再取 top3。  
   ✅ 做完标志：`len(ranked)` 小于 10（说明有段落被筛掉了），且输出里没出现 `rocket` `Falcon` 相关句子。

3. **存结果**：把 top3 段落写进 `reranked_chunks.json`，格式为 `{"chunks": ["...", "...", "..."]}`。  
   ✅ 做完标志：文件生成，用 `cat reranked_chunks.json` 能看到合法 JSON，且含三个字符串。

## 自测

<details><summary>Q1：如果把 embedding 模型换成 `text-embedding-ada-002`，相似度分数还能直接比大小吗？</summary>
可以。同一模型产出的向量，点积/余弦值具备相对可比性。不同模型之间不能跨模型比分数，但本题只用一个模型，没问题。
</details>

<details><summary>Q2：下面这行代码有没有问题？为什么？</summary>
```python
scores = [np.dot(query_emb, emb.embedding) for emb in chunk_embs]
```
有问题。`np.dot` 返回 `numpy.float64`，OpenAI Python SDK 某些版本会拒绝传给 `json.dumps`。应显式转成 `float()`，如答案代码所示。
</details>

<details><summary>Q3：“用小模型打分”这步，能不能用 `gpt-3.5-turbo` 调用 `messages=[{"role":"user","content":"这段和问题相关吗？请只回答是或否"}]` 来替代？</summary>
理论上能，但不推荐。它慢、贵、不稳定（可能返回"yes."或"YES！"或"相关"），而且没提供量化分数，没法排序。embedding 是专为相似度设计的，又准又快。
</details>

## 下一章为什么是它

这一章筛出了 3 段靠谱原文，但还没让模型“真干活”。  
下一章《让大模型精读这三段》就要把它们喂给 `gpt-4o`，让它基于这三段写答案、改代码、列参考文献——不带 hallucination 地干活。  
没有这一章的筛选，下一章就是拿一堆噪音去喂大模型，白花 token 还答不准。
