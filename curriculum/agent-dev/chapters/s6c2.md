# 第 19 章 向量不是玄学，是数字比大小

## 这一章要解决什么

你让 Agent 查资料，它翻出三段文档，挑最相关的给你。你问“为啥是这三段”，它说“因为它们最像你的问题”。

但“像”是什么？不是人眼扫一眼觉得像，也不是模型心里有个模糊印象——  
**它是把每句话变成一串数字，然后拿计算器算哪两串数字更“指向同一个方向”。**

就像你搜“Python 怎么读 Excel”，它不靠关键词硬匹配（否则会漏掉“pandas read_excel”这种没出现“Excel”但实际在干这事的句子），而是把这句话和所有文档段落都转成向量，再比距离。

这一章就把这个“转数字→比距离”的过程拆开：  
不调 OpenAI 的 API（太黑盒），直接跑一个开源 embedding 模型；  
亲眼看到“hello”和“hi”变成的两个向量，余弦值接近 0.9；  
而“hello”和“banana”的向量，余弦值可能只有 0.1。

## 核心概念

### 向量就是一串固定长度的数字  
不是玄学坐标，就是 Python 里的 `list[float]` 或 `np.array`。长度由模型定（比如 384 或 1024），每个数字可正可负，代表这个词/句在某个抽象维度上的“强度”。

### 余弦相似度 = 看方向，不看长短  
两个向量点乘 ÷ 它们各自长度的乘积。结果在 -1 到 1 之间。越接近 1，说明它们“指向几乎同一个方向”，语义越像。  
（不用管公式推导——你只用 `scipy.spatial.distance.cosine` 取 1 减它，就得到相似度）

### Embedding 模型就是个“句子翻译器”  
输入文本，输出数字串。它不回答问题、不生成代码，只做这一件事。训练时喂它大量句子对（比如“你好”和“hello”），让它学会：语义近的句子，输出的数字串也要近。

## 先跑起来

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("all-MiniLM-L6-v2")  # 开源小模型，秒装秒跑

texts = ["Python 怎么读 Excel", "pandas read_excel 用法", "香蕉富含钾元素", "如何用 openpyxl 写入表格"]
embeddings = model.encode(texts)

# 算第一句和其余三句的相似度
q_vec = embeddings[0]
sim_scores = [1 - np.dot(q_vec, e) / (np.linalg.norm(q_vec) * np.linalg.norm(e)) for e in embeddings[1:]]

print("相似度（从高到低）：", [f"{s:.3f}" for s in sorted(sim_scores, reverse=True)])
# 你会看到类似：['0.721', '0.685', '0.112'] —— 前两个明显高，第三个几乎不相关
```

> ✅ 跑完能看到三个数字：前两个大（语义近），最后一个很小（不相关）。这就是“向量比大小”的全部真相。

## 自测

<details><summary>1. 为什么不用欧氏距离，而用余弦相似度？</summary>
因为余弦只看方向，不看长度。一句话说 10 遍，embedding 向量长度会变大，但方向几乎不变——余弦值稳定；欧氏距离会暴增，误判为“不相似”。
</details>

<details><summary>2. 这行代码 `1 - scipy.spatial.distance.cosine(a, b)` 的结果是 0.85，那 a 和 b 的余弦值是多少？</summary>
0.15（cosine 函数返回的是夹角余弦值，范围 [-1,1]；distance.cosine 返回的是 1 - 余弦值，所以余弦值 = 1 - 0.85 = 0.15）
</details>

<details><summary>3. 如果把 query 改成 "香蕉怎么吃"，和 "香蕉富含钾元素" 的相似度一定比和 "Python 怎么读 Excel" 高吗？</summary>
不一定。虽然都有“香蕉”，但 embedding 模型学的是语义，不是字面。如果训练数据里“香蕉怎么吃”常和“剥皮”“切片”一起出现，而“香蕉富含钾”总和“营养”“补钾”共现，它们的向量方向可能反而更远。
</details>
