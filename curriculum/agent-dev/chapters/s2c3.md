# 第 6 章 让模型老老实实输出JSON

## 这一章要解决什么

你让它“把商品列表转成 JSON，字段是 name/price/unit”，它回你：

```text
好的！这是你要的 JSON：
{
  "name": "苹果",
  "price": 5.8,
  "unit": "斤"
}
```

——结果你 `json.loads()` 一下，报错：`Expecting property name enclosed in double quotes`。

再一看，它前面多写了那句“好的！这是你要的 JSON：”，后面可能还跟了个句号。或者 price 写成了 `5.8元`，或者 unit 是 `"个"` 但你要求必须是 `"kg"` 或 `"g"`。

不是它不听话，是它根本没被“锁死”在 JSON 格式里。  
这一章就教你怎么给它上一把**JSON 锁**：用 schema 告诉它“只准输出这个结构”，再加一层兜底——它乱来？那就重试，直到吐出合法 JSON。

---

## 核心概念

### 1. JSON Schema 不是装饰，是铁栅栏  
OpenAI 的 `response_format={"type": "json_object"}` + `tools`（或 `strict=True`）不是“建议它输出 JSON”，而是让模型在 token 级别就被约束：它每猜一个字符，都要符合 schema 定义的语法树。没双引号？直接卡住。

### 2. 模型不会“解析失败”，它只会“输出非法字符串”  
`json.loads()` 报错 ≠ 模型错了。模型只是按提示词生成了文本，而你的代码没做容错。  
真正的容错不是改模型，是改你调它的那几行 Python：捕获 `json.JSONDecodeError`，打日志，重发请求。

### 3. 正则提取是临时拐杖，不是终点  
当 `response_format` 不支持（比如老模型）、或你只想捞出 `{...}` 片段时，用 `re.search(r"\{.*?\}", text, re.DOTALL)` 能救急。但它不校验字段类型、不检查必填项——所以只用在重试前的“最后一捞”。

---

## 先跑起来

```python
import os
import json
import openai
import re

client = openai.OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

prompt = "列出三种常见水果，返回 JSON 格式，包含字段 name（字符串）、price（数字）、unit（字符串，只能是 'kg' 或 'g'）。不要任何解释，只输出 JSON 对象。"

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": prompt}],
    response_format={"type": "json_object"},
    temperature=0.0,
)

raw_text = response.choices[0].message.content
print("原始输出：", repr(raw_text))

# 尝试直接解析
try:
    data = json.loads(raw_text)
    print("✅ 解析成功：", data)
except json.JSONDecodeError as e:
    print("❌ 解析失败：", e)
    # 用正则捞一次大括号内容（防开头有废话）
    match = re.search(r"\{[^{}]*\}", raw_text, re.DOTALL)
    if match:
        try:
            data = json.loads(match.group())
            print("✅ 正则捞出并解析成功：", data)
        except:
            print("❌ 正则也救不了")
```

你会看到：大概率第一遍就成功；如果失败，`repr()` 会暴露它偷偷加了换行、注释、甚至中文引号。`re.search` 那行能捞出 `{...}`，但不保证字段对。

## 动手练

1. **写一个严格 schema 提示词**  
   让模型返回 `{"city": "北京", "temperature": 25, "unit": "celsius"}`，其中 `unit` 只能是 `"celsius"` 或 `"fahrenheit"`。  
   ✅ 做完：`json.loads()` 不报错，且 `data["unit"] in ["celsius", "fahrenheit"]` 为 `True`。

2. **加一层重试逻辑**  
   把上面代码改成最多重试 3 次：每次失败后，打印错误、sleep 0.5 秒，再发一次请求（提示词不变）。  
   ✅ 做完：即使第一次失败，最终也能拿到合法 JSON 并通过字段校验。

3. **手动提取 + 字段验证**  
   故意把 `response_format` 删掉，只靠正则提取 `{...}`，然后手动检查 `data.get("temperature")` 是 `int` 或 `float`，且 `data.get("city")` 是非空字符串。  
   ✅ 做完：输出 `"字段校验通过"`，且 `type(data["temperature"]) in (int, float)` 为 `True`。

## 自测

<details><summary>1. 如果把 <code>response_format={"type": "json_object"}</code> 换成 <code>response_format={"type": "text"}</code>，模型输出 JSON 的概率会变高吗？</summary>
不会。`response_format` 是强制约束，不是概率引导。设成 `"text"` 就等于放弃约束，模型爱怎么输出都行。
</details>

<details><summary>2. 下面这段代码有没有问题？<br><code>json.loads('{\"name\": \"苹果\", \"price\": \"5.8元\"}') </code></summary>
有问题。`"5.8元"` 是字符串，但 schema 要求 `price` 是数字。`json.loads` 能解析成功（因为 JSON 语法合法），但后续字段校验会失败。
</details>

<details><summary>3. 为什么不能只靠 <code>re.search(r"\{.*\}", text)</code> 而不用 <code>re.DOTALL</code>？</summary>
因为默认 `.` 不匹配换行符。如果模型输出跨多行的 JSON（比如 `{` 换行后才写 `"name": ...`），`.*` 会停在第一行末尾，匹配不到完整对象。
</details>
