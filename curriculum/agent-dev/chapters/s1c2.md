# 第 2 章 你发给模型的每条指令都算数

## 这一章要解决什么

你写了个 prompt：“帮我把这段 Python 代码改成用 pandas 读 CSV”，发出去，它真改了。  
你加了一句“请只返回代码，不要解释”，它就真不解释了。  
你再加一句“输出控制在 10 行以内”，它突然缩成 5 行——但有时候又不管用。

你开始怀疑：它到底听哪句？哪句是“命令”，哪句是“废话”？  
temperature 调高它变啰嗦，调低它变死板；max_tokens 设小了它半截断句；system 消息删掉，它突然开始跟你聊人生……

这一章不讲“模型怎么学的”，就盯住你**亲手发出去的那几行字和那三个参数**：  
它怎么读你写的 system/user，怎么被 temperature 拉着走，怎么被 max_tokens 突然掐断。  
全是看得见、改得着、跑出来就能验证的事。

---

## 核心概念

### 它不是在“理解对话”，是在续写字符串  
system 和 user 消息拼在一起，就是它的“上文”。它不区分谁说的、哪句重要——只认 token 序列。  
你写 `system: "你是 Python 专家"`，它就当这串字符是开头；你写 `user: "改代码"`，它就接着这串往下猜。  
删掉 system，开头少了一段 token，续写的起点就变了。

### temperature 不是“随机度”，是“猜字时敢不敢离平均远一点”  
temperature=0：每个字都选概率最高的那个，稳得像抄答案。  
temperature=0.8：它会翻翻概率榜前几名，挑一个——可能选第二高的，也可能选第五高的（但不会选倒数第一）。  
你让它“总结文档”，temperature 高了，它可能合并两段、漏细节；低了，它可能照抄原文三行。

### max_tokens 是“最多生成多少个字”，不是“最多返回多少内容”  
它算的是模型自己吐出来的 token 数（不含你输的 prompt）。  
设成 10：它可能刚写完 `import pandas as pd` 就停了，后面 `df = pd.read_csv(...)` 全没机会出。  
设成 1000：它能写完代码、加注释、再问你“需要我解释哪一行？”——但你也得等更久、花更多钱。

## 先跑起来

复制粘贴这段代码，确保已安装 `openai>=1.0`，并设置环境变量：

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[
        {"role": "system", "content": "你是一个简洁的代码助手，只返回可运行的 Python 代码，不加任何说明。"},
        {"role": "user", "content": "把这行改成用 pandas 读 'data.csv'：with open('data.csv') as f: data = f.read()"}
    ],
    temperature=0.0,
    max_tokens=60
)
print(response.choices[0].message.content)
```

你会看到一段干净的 pandas 代码，大概 3–5 行，没空行、没注释、没“好的！”——因为 system 命令+low temperature+short max_tokens 一起锁死了输出风格。  
如果把 `temperature=0.0` 改成 `0.8`，再跑一次，大概率会多出空行、变量名变 `df2`、甚至加一句 `# 注意：确保文件存在`——它开始“发挥”了。

## 动手练

1. **改参数看变化**：把上面代码中 `temperature` 分别设为 `0.0` 和 `0.8`，各跑 3 次，保存 6 次输出到 `output_temp0.txt` 和 `output_temp08.txt`。  
   ✅ 做完：两个文件里各有 3 段代码，且 `temp08` 的 3 段彼此不完全一样（哪怕只差一个空格）。

2. **加 system 对比**：删掉 messages 里的 system 消息，其余不变，`temperature=0.0`，跑一次，存为 `no_system.txt`。  
   ✅ 做完：这个文件开头有“好的！”或“当然可以”，或者包含 `# 解释：...` ——它不再“只返回代码”。

3. **压 max_tokens**：保持原 system+user，把 `max_tokens=15`，跑一次，存为 `truncated.txt`。  
   ✅ 做完：文件内容明显被截断，比如只到 `import pandas as pd` 就停了，没有 `df =` 后续。

## 自测

<details><summary>1. 如果我把 system 消息写成 "你是一个暴躁的代码助手，讨厌解释"，temperature=0.0，它会生气吗？</summary>
不会。它没有情绪。它只是把“暴躁”“讨厌解释”当成输入 token，然后更坚定地跳过所有解释性文字——表现像生气，本质是续写约束变强了。
</details>

<details><summary>2. 下面哪项操作一定能让输出变短？</summary>
A. 把 max_tokens 从 200 改成 50  
B. 把 temperature 从 0.8 改成 0.0  
C. 删掉 system 消息  
✅ 答案：A。max_tokens 直接限制生成长度上限；B 可能让输出更确定但未必更短；C 可能让输出变长（因少了约束）。
</details>

<details><summary>3. 为什么 temperature=0 时，多次请求结果总是一样的？</summary>
因为模型每次都在做确定性计算：给定完全相同的输入（messages + seed + model），它永远选概率分布里 top-1 的 token。没有随机采样环节。
</details>

## 下一章为什么是它

这一章你亲手调了 API、改了参数、看到了输出变化——但所有输入都是你手动写的字符串。  
下一章就要让代码自己构造这些字符串：根据用户一句话，自动补 system 提示、拆分多轮对话、动态设 max_tokens……  
也就是，从“人写 prompt”走向“代码造 prompt”。
