# 第 26 章 从失败记录里攒测试题

## 这一章要解决什么

你昨天刚上线的「自动修 Bug」Agent，今天收到用户消息：“我让它把 `for i in range(10)` 改成倒序，它输出了 `for i in reversed(range(10))` ——但这段代码在 Python 2 里根本跑不了！”

你翻日志，看到报错：`NameError: name 'reversed' is not defined`。  
你心里一紧：**这不是模型瞎编，是它真没看清你的约束**。

这一章不教你怎么写更漂亮的提示词。  
它教你干一件更实在的事：**从真实失败里，直接扒出一道题——有输入、有你想要的输出、有它实际吐出来的错答案、还有错在哪**。  
就像老师改卷子，不是光打叉，而是把这道错题抄下来，下次考前再练一遍。

---

## 核心概念

### 失败日志 ≠ 错误堆栈  
日志里那句 `{"input": "...", "output": "...", "error": "..."}` 不是噪音，是原始题干。你只需要把它“翻译”成测试用例格式：输入是什么？你当时期望它输出什么？它实际输出了啥？为什么算错？

### “可复现”就一条标准：你本地一跑，它立刻重演  
不用等线上流量、不用 mock 用户行为。只要把 input 塞进你现在的 Agent 函数，它必须稳定输出那个错答案。如果它有时对有时错——先跳过，那是稳定性问题，不是测试题问题。

### 测试题不是越多越好，而是“能戳中一个具体弱点”  
比如：  
- 它把 `os.path.join("a", "b")` 改成了 `"a/b"`（漏了平台兼容性）→ 这是一道题；  
- 它把所有中文标点都换成英文（但你没提要求）→ 这是另一道题；  
- 它连续三次把 `len()` 写成 `length()` → 这不是一道题，是同一个 bug 的三次回声，只记一次。

---

## 先跑起来

把下面这段代码存成 `extract_test_case.py`，确保你环境里装了 `openai>=1.0`，且 `OPENAI_API_KEY` 已设在环境变量里：

```python
import json
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

# 模拟一条真实失败日志（你替换成自己日志里的 actual_input / actual_output）
log = {
    "input": "把这段 Python 代码改成支持 Python 2 和 Python 3：for i in range(10): print(i)",
    "actual_output": "for i in reversed(range(10)):\n    print(i)",
    "error": "NameError: name 'reversed' is not defined"
}

prompt = f"""你是一个测试题提取器。请严格按 JSON 格式输出：
{{
  "input": "...",
  "expected_output": "...",
  "actual_output": "...",
  "failure_reason": "..."
}}
要求：
- input 必须和日志里完全一致；
- expected_output 是你作为开发者，希望它这次输出的、能通过的代码；
- actual_output 必须和日志里完全一致；
- failure_reason 要具体（比如'用了 Python 3 特有函数'，不能写'回答错误'）。
"""

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.1,
    max_tokens=512,
    response_format={"type": "json_object"}
)

parsed = json.loads(response.choices[0].message.content)
print(json.dumps(parsed, indent=2, ensure_ascii=False))
```

运行后你会看到类似这样的输出：

```json
{
  "input": "把这段 Python 代码改成支持 Python 2 和 Python 3：for i in range(10): print(i)",
  "expected_output": "for i in xrange(10):\n    print i",
  "actual_output": "for i in reversed(range(10)):\n    print(i)",
  "failure_reason": "用了 Python 3 特有函数 reversed，Python 2 中不存在"
}
```

注意：如果 `response_format` 报错（老模型不支持），就把那行删掉，手动 `json.loads()` 也行。

## 自测

<details><summary>1. 如果某条日志里没有 `input` 字段，只有用户发来的 raw text，还能当测试题用吗？</summary>
可以。只要你知道那段 text 是什么（比如微信聊天截图里的文字），就把它当作 input。测试题不要求字段名匹配，只要你知道“这是给它的输入”。
</details>

<details><summary>2. 下面这个 JSON 算合格的测试题吗？</summary>
```json
{
  "input": "总结一下这篇论文",
  "expected_output": "一段清晰的摘要",
  "actual_output": "略略略",
  "failure_reason": "没给出具体内容"
}
```
不合格。“expected_output” 必须是**确定的字符串**，不能是描述（如“一段清晰的摘要”）；“actual_output” 也不能是“略略略”，得是它真实吐出的字。否则没法自动化断言。
</details>

<details><summary>3. 为什么不能直接拿报错信息（比如 `KeyError: 'user_id'`）当 failure_reason？</summary>
因为报错信息是程序视角，而 failure_reason 要是人视角：它为什么错？比如“没检查输入字典是否含 user_id 字段”，而不是“KeyError”。前者能指导你改提示词或加校验逻辑，后者只能让你查 Python 文档。
</details>
