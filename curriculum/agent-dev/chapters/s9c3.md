# 第 31 章 现在别硬刚的事

## 这一章要解决什么

你让模型查完文档，改完代码，再写个周报发到钉钉——它真干了，还干得挺像样。你一激动，就去跟老板说：“下周起，周报全自动！”

结果周一早上，它把上周三的会议纪要塞进“本周重点”，把没发生的项目进度标成“已完成”，还顺手@错了三个已经离职的同事。

这不是提示词没写好。是它**根本没能力做这件事**——不是“现在调不好”，是“永远不可能靠猜下一个字来做到”。

这一章不教你怎么写提示词，教你**什么时候该立刻停手、别浪费时间**。

---

## 核心概念

### 它没有记忆，只有上下文  
它不记得昨天聊过啥，也不记得你上条消息里说“张工负责后端”。它只看当前 `messages` 列表里这几十行字。你删掉上文，它就“失忆”。Agent 加个 memory 模块？那只是帮你拼字符串，不是它真记住了。

### 它不理解“事实”，只匹配模式  
你说“Python 的 `list.append()` 时间复杂度是 O(1)”，它能复述；你说“`list.pop(0)` 是 O(n)”，它也能接上。但它没查过 CPython 源码，也没跑过 benchmark。它只是见过太多类似句式。你让它查“2024 年 3 月 GitHub 上 star 最多的 Rust 项目”，它大概率编一个名字出来——因为训练数据里没这串 token。

### 它不会做闭环验证  
你让它“检查代码有没有空指针”，它能写一段分析；但你没法让它真的运行一遍、捕获 panic、再回来看哪行触发的。它不连终端，不读 stderr，不改环境变量。所有“验证”都是用语言再猜一遍语言。

## 先跑起来

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

resp = client.chat.completions.create(
    model="gpt-4-turbo",
    messages=[{"role": "user", "content": "请告诉我：今天北京的实时气温是多少摄氏度？"}],
    temperature=0.0,
)
print(resp.choices[0].message.content)
```

运行后，你会看到它要么编一个数字（比如“22℃”），要么说“我无法获取实时天气”。  
**注意：它不会去调高德 API，也不会打开浏览器。它只在训练数据里找最像这句话的答案。**  
如果报错 `AuthenticationError`，说明密钥没设对；如果报错 `NotFound`，换 `gpt-3.5-turbo` 再试。

## 动手练

1. **查真实数据**：用上面代码问“2024 年 6 月 15 日上海地铁 10 号线早高峰最小行车间隔是多少秒”，保存输出。  
   ✅ 做完：你得到一段文字，且里面明确写了“秒”这个单位（哪怕数字是错的）。

2. **跨会话状态追踪**：新开一个 Python 文件，先问“把‘foo’转成大写”，再问“上一步结果加 ‘_bar’”，运行两次独立请求（不传 history）。  
   ✅ 做完：第二次输出是 “FOO_bar” 或类似字符串（说明它没记住第一次结果）。

3. **红绿灯清单**：新建 `agent_limits.md`，写下三条红灯项，格式如：  
   `🔴 实时查未公开数据库` —— 它没权限，也没连接方式。  
   ✅ 做完：文件里有且仅有 3 条 `🔴` 开头的条目，每条附一句话原因。

## 自测

<details><summary>1. 为什么让 Agent “自动修复 CI 失败的 PR” 在当前技术下不可行？</summary>
因为它看不到 CI 的真实日志（stderr/stdout）、不能执行 `git checkout`、不能改 `.github/workflows/` 下的 YAML、也不能触发重跑。所有“修复”只能基于你喂给它的、可能已过期或截断的日志文本去猜。
</details>

<details><summary>2. 判断正误：只要把 temperature 设为 0，模型就能稳定输出正确答案。</summary>
错误。temperature=0 只保证每次选概率最高的 token，但最高概率的 token 序列仍可能是错的（比如训练数据里错误答案更常见）。
</details>

<details><summary>3. 如果客户说“让它每天早上 9 点自动汇总飞书文档并邮件发送”，你该怎么拒绝？</summary>
“它没法主动触发定时任务，也读不了飞书未授权的文档，更发不了邮件——这些都得由你自己的服务来调度、鉴权和发送。我们能做的，只是在你把内容喂给它之后，帮它润色或归类。”
</details>
