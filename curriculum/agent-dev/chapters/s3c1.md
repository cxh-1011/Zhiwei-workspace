# 第 7 章 模型其实不会调工具

## 这一章要解决什么

你让它“查一下北京今天天气”，它真就返回了一段 JSON，里面写着 `"name": "get_weather", "arguments": {"city": "北京"}`。  
你一激动，以为它已经连上天气 API、拿到数据、还帮你格式化好了。

这一章要把这个错觉拆掉。**模型从不调用函数，它只输出字符串——碰巧这串字符串长得像函数调用的 JSON。**  
真正去发 HTTP 请求、解析响应、填进 `{"temperature": 26}` 里的，是你写的那几行 `if name == "get_weather": ...`。

就像你让同事帮你“把 Excel 第三列转成小写”，他没真开 Excel，只是写了行 Python 代码交给你——执行代码的是你，不是他。

## 核心概念

### 模型只管“写”，不管“做”  
它看到 `{"role": "user", "content": "查北京天气"}`，就按训练时见过的 pattern，输出一个 `{ "name": "get_weather", ... }` 字符串。  
它不认得 `get_weather` 是函数还是菜名，也不关心 API 地址在哪。它只学过：“用户问天气 → 下一行大概率是这种 JSON”。

### tools 是你给它的“字典”，不是“插件”  
你传给 `client.chat.completions.create(..., tools=[...])` 的那个 `tools` 列表，本质是一份格式说明书：  
- 告诉模型：“如果要调天气，就照这个 JSON 结构写”  
- 告诉你自己的代码：“如果模型输出匹配这个结构，就去执行对应函数”  
模型不会读 `tools` 里 `description` 的中文，它只记住了 `{"name":"get_weather","parameters":{"type":"object","properties":{"city":{"type":"string"}}}}` 这种 token 序列的 pattern。

### function calling 是两段代码拼起来的活  
第一段（模型干的）：输入 prompt → 输出字符串 `{"name":"get_weather","arguments":"{\"city\":\"北京\"}"}`  
第二段（你干的）：检查字符串是否合法 → 提取 `name` 和 `arguments` → `json.loads(arguments)` → 调 `get_weather("北京")` → 把结果塞回对话再喂给模型  

少哪一段，都算不上“调用了工具”。

## 先跑起来

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[{"role": "user", "content": "查上海天气"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的当前天气",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"]
            }
        }
    }],
    tool_choice="auto"  # 让模型自己决定要不要调
)

msg = response.choices[0].message
print("模型输出的内容：")
print(msg.content)  # 可能是 None（如果选了调工具）
print("模型选择的工具：")
print(msg.tool_calls)  # 看到 [ChatCompletionMessageToolCall(id='...', function=Function(name='get_weather', arguments='{...}'))]
```

跑完你会看到：`msg.content` 是空的（因为模型选了调工具），而 `msg.tool_calls` 是一个列表，里面包着它生成的 JSON 字符串——注意，`arguments` 是字符串，不是 dict！它还没被 `json.loads` 过。

## 动手练

1. **手写模拟输出**：在纸上或编辑器里，写一段纯文本对话。用户说“查深圳天气”，你**只扮演模型**，写出它可能输出的完整 `tool_calls` 内容（就是那个带 `id`、`name`、`arguments` 的字典结构）。做完标准：复制粘贴到 Python 里能 `json.loads()` 成功。

2. **手动补全参数**：用户说“查杭州和苏州的天气”，你手写模型输出。要求 `arguments` 里必须有 `city` 字段，且值是字符串（不能是列表）。做完标准：`json.loads(你写的arguments)["city"]` 返回 `"杭州和苏州"` 或 `"杭州,苏州"` 都算对（只要它是字符串）。

3. **找错别字**：下面这段模型输出有 2 处硬错误（会导致你代码 `json.loads` 失败或字段名错）：
   ```json
   {"name": "get_weather", "arguments": "{"city": "广州"}"}
   ```
   做完标准：标出哪两个字符错了，并写出修正后的完整字符串。

## 自测

<details><summary>1. 如果我把 tools 删掉，只留 tool_choice="auto"，模型还会输出 tool_calls 吗？</summary>
不会。`tools` 是模型生成 `tool_calls` 的前提。没有 `tools`，`tool_choice` 就没意义，模型只会走常规文本生成流程。
</details>

<details><summary>2. 这段代码有没有问题？</summary>
```python
tool_call = msg.tool_calls[0]
city = tool_call.function.arguments["city"]  # ❌ 错在这里
```
有问题。`tool_call.function.arguments` 是字符串，不是 dict。正确写法是 `json.loads(tool_call.function.arguments)["city"]`。
</details>

<details><summary>3. 为什么模型有时会输出 {"name": "get_weater", ...}（拼错）？</summary>
因为它没见过正确的拼写，或者训练数据里混进了错别字样本。它不是查字典，是猜下一个 token——"weater" 和 "weather" 在 token 表里可能就差一个 subword，概率差不多。
</details>

## 下一章为什么是它

这一章只让模型“写 JSON”，但没让它“看到 JSON 执行后的结果”。  
下一章《让模型看见它调用的结果》就要补上后半段：怎么把 `get_weather("北京")` 返回的 `{"temperature": 26}` 塞回对话，让模型接着推理——这才是闭环。
