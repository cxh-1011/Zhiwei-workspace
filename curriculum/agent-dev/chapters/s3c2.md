# 第 8 章 工具描述怎么写才管用

## 这一章要解决什么

你写了个查快递的函数，还配了段话：“这个函数能查物流，输入单号就行”。  
把它塞给模型，它真调了——但传进去的是 `"顺丰SF123456"`，而你的函数只收纯数字单号。  
或者更糟：它压根没选这个函数，转头自己编了个 `get_tracking_info()` 调用了。

不是它懒，是它看不懂你写的“说明”。

这一章就干一件事：**把人话翻译成模型能 parse 的说明书**。  
不是让它“理解”快递，是让它能准确识别：什么时候该用、参数叫什么、必须填几个、填错会报错。

就像你给新同事交班，不能说“你看着办”，得写清：“接口地址是 `/track`，`number` 是字符串、必填，`carrier` 是可选字符串，值只能是 `'sf'` `'zto'` `'yto'`”。

---

## 核心概念

### 工具名不是随便起的  
模型靠名字匹配意图。`calculate` 比 `do_math` 好；`track_package` 比 `get_info` 强。  
名字里带动词+名词，小写字母+下划线，别缩写。它不查词典，只看字面像不像。

### 描述必须告诉模型“它该不该用”  
❌ “查询物流信息”  
✅ “根据快递单号和快递公司代码，返回实时物流轨迹（仅支持顺丰、中通、圆通）”  
重点：触发条件（单号+公司）、能力边界（只支持三家）、输出类型（轨迹列表）。模型不推理，只匹配关键词。

### 每个参数必须声明类型和是否必填  
`"number": {"type": "string", "description": "12位纯数字单号，不含字母或空格"}`  
不是“用户输入的单号”——模型不知道“用户输入”指啥。  
`"carrier": {"type": "string", "enum": ["sf", "zto", "yto"], "description": "快递公司代码"}`  
没写 `enum`？它可能传 `"shunfeng"` 或 `"SF"`，你的后端直接 400。

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

tools = [{
    "type": "function",
    "function": {
        "name": "add_numbers",
        "description": "把两个整数相加，返回结果",
        "parameters": {
            "type": "object",
            "properties": {
                "a": {"type": "integer", "description": "第一个整数"},
                "b": {"type": "integer", "description": "第二个整数"}
            },
            "required": ["a", "b"]
        }
    }
}]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "37 加 82 等于多少？"}],
    tools=tools,
    tool_choice="auto"
)

print(response.choices[0].message.tool_calls)
```

你会看到类似这样的输出：  
`[ChatCompletionMessageToolCall(id='call_xxx', function=Function(name='add_numbers', arguments='{"a": 37, "b": 82}'), type='function')]`  
注意两点：  
1. 模型没自己算，而是调了你定义的工具；  
2. `arguments` 是合法 JSON 字符串，`a` 和 `b` 都是整数，没加引号。

如果把 `parameters` 里 `a` 的 `type` 改成 `"string"`，它就会传 `"37"`——字符串，不是数字。

## 动手练

1. **改错题**：下面这段工具描述有问题，复制进 Python 跑一下，看它生成的 `arguments` 是不是整数：  
   ```json
   {"name":"add","description":"加两个数","parameters":{"type":"object","properties":{"a":{"description":"第一个数"},"b":{"description":"第二个数"}},"required":["a","b"]}}
   ```  
   ✅ 做完：运行后 `arguments` 里 `a` 和 `b` 是字符串（带引号），不是整数。

2. **补全题**：给定函数 `def get_weather(city: str, unit: str = "c") -> dict:`，补全它的 `parameters` 字段（只写 `properties` 和 `required` 部分）。  
   ✅ 做完：`unit` 不在 `required` 里，且 `unit` 的 `enum` 是 `["c", "f"]`。

3. **实战题**：为查快递接口 `def query_express(number: str, carrier: str) -> dict:` 写完整 `function` schema。要求：  
   - `number` 是非空字符串，长度 10–20；  
   - `carrier` 只能是 `"sf"` `"zto"` `"yto"`；  
   - 名字叫 `"query_express"`；  
   - 描述要让模型知道“只有用户明确说了单号和快递公司时才用”。  
   ✅ 做完：粘贴进上一节代码替换 `tools`，提问“查单号 SF123456789 的顺丰物流”，它调 `query_express` 且 `arguments` 合法。

## 自测

<details><summary>1. 下面哪个 parameter 描述会让模型传字符串 `"123"` 而不是数字 `123`？</summary>
A. `"type": "integer"`  
B. `"type": "number"`  
C. `"type": "string"`  
D. 缺少 `type` 字段  
→ 答案：C 和 D（没声明类型时默认 string）
</details>

<details><summary>2. 为什么 `description` 里写“快递公司简称”不如写“快递公司代码，值只能是 'sf' 'zto' 'yto'”？</summary>
因为模型不会查“简称”对应表。它只做字符串匹配和枚举校验。“简称”太模糊，它可能传 `"shunfeng"` 或 `"顺丰"`，而 `enum` 能硬性约束。
</details>

<details><summary>3. 如果工具函数实际接收 `carrier: Optional[str]`，但 schema 里没写 `carrier` 在 `required` 中，模型会不会传 `carrier`？</summary>
会。只要用户提到了快递公司，它就可能传；没提，就可能不传。`required` 控制的是“必须传”，不是“可以传”。
</details>

## 下一章为什么是它

这一章你写了能让模型看懂的工具说明书。  
但光有说明书不够——模型可能选错工具，比如用户问“今天北京热不热”，它却去调查快递。  
下一章《工具调用怎么兜得住》就教你怎么加一层判断：让模型先决定“该不该调”，再决定“调哪个”，最后才填参数。
