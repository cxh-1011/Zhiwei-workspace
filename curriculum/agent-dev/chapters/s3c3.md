# 第 9 章 工具报错后让它自己改

## 这一章要解决什么

你写了个查天气的 Agent，让它问“北京今天热不热”，它真去调了 `get_weather(city="北京")`——结果报错：`TypeError: get_weather() missing 1 required keyword argument: 'unit'`。

你盯着错误发愣：它明明知道要传 `unit`，怎么就忘了？

这不是它“忘了”。是它根本没看见这个报错。

这一章就干一件事：**把报错塞回对话里，让它自己读、自己改、自己重试**。  
不是你手动改代码，不是你换提示词硬压它——是它看到 `missing unit`，就主动补上 `"unit": "celsius"`，再交出一份合法 JSON。

这才是 Agent 能自己干活的第一步。

---

## 核心概念

### 报错不是日志，是上下文的一部分  
工具调用失败时抛出的异常信息（比如 `city not found` 或 `unit must be 'celsius' or 'fahrenheit'`），不是丢给 `print()` 就完事的。你要把它变成 `messages` 里的一条 `assistant` + `tool` + `user` 三段式记录，模型才“知道”刚才哪错了。

### 模型不会自动重试，得靠你“喂”对格式  
OpenAI 的 `tools` 接口本身不支持自动重试。你得在 catch 到异常后，手动把 `tool_calls`、错误信息、以及 `tool_call_id` 塞进下一轮 `messages`，像这样：
```python
{"role": "tool", "tool_call_id": "...", "content": "{'error': 'unit is required'}"}
```
少一个字段，它就当没这回事。

### 合法 ≠ 看着像，得真能被 `json.loads()` 解析  
它第二次输出的 `tool_calls` 字段，必须是语法正确的 JSON 对象（不是带省略号的、不是用中文引号的、不能有多余逗号）。你得用 `json.loads()` 验证，而不是只看 `if "unit" in response`。

---

## 先跑起来

复制粘贴这段代码，装好 `openai>=1.0` 和 `pydantic`（用于验证 JSON）：

```python
import os
import json
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

def get_weather(city: str, unit: str = "celsius"):
    if unit not in ["celsius", "fahrenheit"]:
        raise ValueError("unit must be 'celsius' or 'fahrenheit'")
    return f"{city} {25 if unit=='celsius' else 77}°{unit[0].upper()}"

# 第一次：故意漏掉 unit → 必然报错
messages = [{"role": "user", "content": "北京今天热不热？"}]
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的当前天气",
            "parameters": {"type": "object", "properties": {"city": {"type": "string"}, "unit": {"type": "string"}}, "required": ["city", "unit"]}
        }
    }]
)

# 提取 tool call 并执行（会报错）
tool_call = response.choices[0].message.tool_calls[0]
try:
    result = get_weather(**json.loads(tool_call.function.arguments))
except Exception as e:
    # 把错误塞回去
    messages += [
        response.choices[0].message,
        {"role": "tool", "tool_call_id": tool_call.id, "content": json.dumps({"error": str(e)})},
    ]
    # 第二次请求：带上错误
    response2 = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        tools=[{"type": "function", "function": {"name": "get_weather", "description": "获取天气", "parameters": {"type": "object", "properties": {"city": {"type": "string"}, "unit": {"type": "string"}}, "required": ["city", "unit"]}}]
    )
    print("第二次输出的参数：", response2.choices[0].message.tool_calls[0].function.arguments)
```

你会看到：第一次报错后，第二次输出类似 `{"city": "北京", "unit": "celsius"}` —— 它真补上了。

## 动手练

1. **改错并运行**：把上面代码里 `get_weather(**json.loads(...))` 这行改成 `get_weather(city="北京")`（删掉 `unit`），确保第一次必报错；运行，确认第二次输出含 `"unit"` 字段。✅ 做完标志：终端打印出含 `"unit"` 的 JSON 字符串。

2. **加一层校验**：在 `response2` 后加一行：`json.loads(response2.choices[0].message.tool_calls[0].function.arguments)`。如果没报 `JSONDecodeError`，说明它输出的是合法 JSON。✅ 做完标志：代码不抛异常，安静结束。

3. **换一个错**：把 `get_weather` 改成只接受 `"shanghai"`（小写），然后让模型查 `"上海"`。捕获 `ValueError` 后塞回去，看它是否把 `"上海"` 自动转成 `"shanghai"`。✅ 做完标志：第二次 `arguments` 里是 `"shanghai"`。

## 自测

<details><summary>1. 如果把错误信息塞进 `content` 时没用 `json.dumps()`，而是直接写 `{"error": str(e)}`，会发生什么？</summary>
模型收不到错误。因为 `content` 字段必须是字符串，Python dict 会被当成 `None` 或引发类型错误，`tool` 消息实际没传进去。
</details>

<details><summary>2. 下面这段 message 序列能否让模型学会修正？为什么？<br>`[{"role":"user","content":"查北京天气"},{"role":"assistant","content":null,"tool_calls":[...]}]` → 报错 → `[..., {"role":"tool","tool_call_id":"...","content":"unit missing"}]`</summary>
不能。缺了 `{"role":"assistant", ...}` 这条消息。`tool` 消息必须紧跟在对应的 `assistant` 消息之后，否则模型不知道这是谁调的、哪个调用错了。
</details>

<details><summary>3. 为什么不能只靠提示词说“如果报错就重试”，而必须把错误塞进 messages？</summary>
模型没有记忆或状态。它每次只看 `messages` 列表。不把错误作为一条 `tool` 消息塞进去，它就真的“看不见”刚才发生了什么。
</details>
