# 第 5 章 少样本示例怎么用才不翻车

## 这一章要解决什么

你写了个提示词：“帮我把这段 Python 代码改成用 pandas 读 CSV”，模型回得挺快，还加了 `df.head()`——可你根本没让它打印。

你又试一次，加了句“只改读取部分，不要加其他代码”，它真就只改了一行……但下一行报错：`NameError: name 'pd' is not defined`。

你懵了：它刚才不是还知道 import 吗？怎么现在忘了？

这不是它“变懒”或“耍滑头”。  
是它根本没记住你上一句说了啥——它只盯着你给它的那几句话，**从头到尾扫一遍，然后猜下一个字**。  
你塞进去的示例，就是它唯一能“学”的上下文。塞错一个，它就学歪；塞太多，它反而找不到重点；塞太像答案，它直接抄，连变量名都照搬。

这一章就干三件事：  
✅ 看清示例在 prompt 里到底起什么作用（不是教模型，是喂它“解题节奏”）  
✅ 判断什么时候必须加、什么时候纯属添乱  
✅ 写出真正干净的示例——不暗示、不越界、不偷偷塞答案  

---

## 核心概念

### 示例不是“教学材料”，是“解题节拍器”  
模型不理解“这是好例子”，它只认模式：你给两段“输入→输出”，它就默认“接下来的输入，也要按这个格式吐输出”。  
所以示例的核心任务，是定**格式、定粒度、定边界**。比如你给的例子全是单行代码替换，它就不会自作主张加注释或 try-catch。

### 少≠好，多≠稳，关键看“干扰比”  
一个示例里，如果 70% 的字在讲背景、解释原理、带情绪词（“注意！千万别漏掉！”），模型大概率会把这句话当成“下一步该写的输出”。  
干净示例 = 输入清晰 + 输出精准 + 中间零废话。多加一句“请务必……”，就可能让它把“请务必”三个字当成输出开头。

### 坏示例最危险的地方：它看起来很对  
比如天气查询任务，你放一个示例：“用户问‘北京明天热吗’，你答‘北京明天最高温28℃，体感较热’”。  
问题来了：模型记住了“体感较热”这个主观判断，但你实际只要数字。它下次遇到“上海后天”，真会编个“体感闷热”出来——而你根本没给过“闷热”的定义。

## 先跑起来

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

prompt = """你是一个严格的代码改写助手，只做一件事：把 requests.get() 替成 httpx.get()，其他全不动。
示例：
输入：import requests; r = requests.get('https://api.example.com')
输出：import requests; r = httpx.get('https://api.example.com')

输入：import requests; res = requests.get(url, timeout=5)
输出：import requests; res = httpx.get(url, timeout=5)

输入：import requests; data = requests.post('https://a.com', json={})
输出："""

completion = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.0,
    max_tokens=64
)
print(completion.choices[0].message.content)
```

运行后你会看到：  
✅ 输出严格是 `import requests; data = httpx.post('https://a.com', json={})` —— 注意：它没改 `post` 成 `get`，也没加 import httpx。  
❌ 如果你删掉两个示例，只留第一个，它可能把第二行也改成 `httpx.get`（误泛化）。  
⚠️ 如果你把示例里的 `httpx.get` 改成 `httpx.AsyncClient().get`，它下次就会开始套 async 框架——哪怕你没提异步。

## 自测

<details><summary>1. 为什么 temperature=0 能让示例更可靠？</summary>
因为 temperature=0 关闭随机性，模型每次都会选概率最高的 token。示例的作用是“锚定最高概率路径”，如果路径本身飘忽，锚就打不牢。</details>

<details><summary>2. 判断正误：加 5 个示例一定比加 2 个效果好。</summary>
错误。示例越多，prompt 越长，有效信息密度越低；模型可能聚焦在最后一条示例的细节上，忽略任务主干。实测常出现“2 个刚好，3 个开始抖，5 个反降质”。</details>

<details><summary>3. 下面这个示例有什么问题？  
输入：git status；输出：请运行 git add . 再 commit</summary>
问题在于：输出不是“git status 的结果”，而是“人该做的操作”。模型会混淆“返回值”和“建议动作”，后续遇到其他命令（如 ls）也可能开始给操作建议，而非输出真实结果。</details>

比如你给的示例里 `httpx.get()` 是对的，但它不知道 `httpx` 没 import 就会报错。
