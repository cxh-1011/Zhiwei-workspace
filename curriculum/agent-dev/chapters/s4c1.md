# 第 11 章 ReAct 循环：想-做-看三步走

## 这一章要解决什么

你让它查“上海明天热不热”，它直接回你“热，32℃”。  
你心里一喜——它真懂！  
结果你让它查“北京后天会不会下雨”，它又瞎编了个“会，概率87%”。

它没在查，它在**编**。  
因为默认模式下，模型根本不会停下来想“我现在该干什么”，更不会去调 API、等返回、再看结果。

这一章要把它拉回人做事的节奏：**想→做→看**。  
不是一口气把答案吐出来，而是：  
- 先想：“要判断热不热，得先拿到温度”  
- 再做：“调天气 API，查上海”  
- 最后看：“哦，32℃，那确实热”

ReAct 不是新模型，就是让老模型**学会分步呼吸**。

---

## 核心概念

### 1. ReAct 是格式，不是魔法  
它靠 prompt 约束输出结构，比如强制模型必须写 `Thought:` `Action:` `Observation:`。  
没有这个格式，模型就默认“一次性输出答案”。有了它，才敢让它调工具——因为你知道它下一步一定写 Action，而不是突然开始抒情。

### 2. 解析比生成更重要  
模型输出一串文本，你得能准确切出哪段是 Thought、哪段是 Action、哪个是参数。  
别指望它永远对齐缩进或加空行。你要写鲁棒的解析逻辑：找关键词、按换行切、容错空格。

### 3. 循环 = 你当裁判  
模型只走一步（比如只输出一个 Action），你来：  
- 提取动作和参数  
- 执行（比如真调一次天气 API）  
- 把 Observation 塞回 prompt，让它继续想  
它永远不知道自己在第几步——是你控制节奏。

---

## 先跑起来

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

prompt = """Answer the following question by thinking step by step.
Use exactly this format:
Thought: I need to...
Action: search
Action Input: "Shanghai weather tomorrow"
Observation: {"city": "Shanghai", "date": "2024-06-15", "temp_c": 32}

Question: Is it hot in Shanghai tomorrow?"""

response = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.0,
    max_tokens=200
)

print(response.choices[0].message.content)
```

运行后你会看到类似这样的输出（可能稍有出入，但结构一致）：  
```
Thought: To determine if it's hot, I need the temperature in Shanghai tomorrow.  
Action: search  
Action Input: "Shanghai weather tomorrow"  
Observation: {"city": "Shanghai", "date": "2024-06-15", "temp_c": 32}  
Thought: 32°C is generally considered hot.  
Final Answer: Yes, it is hot in Shanghai tomorrow.
```

注意两点：  
- `Observation:` 后面是你硬塞进去的模拟结果，不是模型生成的；  
- 模型真的按格式写了 `Thought` → `Action` → `Observation` → 新 `Thought`。

## 动手练

1. **改 prompt，让它查北京后天天气**  
   - 把上面代码里的 `"Shanghai weather tomorrow"` 换成 `"Beijing weather day after tomorrow"`，再把问题改成对应句子  
   - ✅ 做完标志：输出里 `Action Input` 是新字符串，且后续 `Thought` 提到“北京”“后天”

2. **写一个 parse_react() 函数**  
   - 输入一段 ReAct 风格文本（比如上面 print 出来的那段）  
   - 输出字典：`{"thought": "...", "action": "...", "action_input": "..."}`  
   - ✅ 做完标志：对任意含 `Thought:`/`Action:`/`Action Input:` 的文本，都能正确提取三字段（大小写、空格、换行都容错）

3. **跑通一次真实循环（不调真天气 API，用 mock）**  
   - 写个函数 `run_react_loop(question)`，内部：  
     • 构造初始 prompt → 调模型 → 解析 →  
     • 如果看到 `Action: search`，就 mock 返回 `{"temp_c": 32}` →  
     • 把 Observation 加进 prompt 继续调模型 →  
     • 直到出现 `Final Answer:`  
   - ✅ 做完标志：输入 `"Is it hot in Shanghai tomorrow?"`，最终输出含 `Yes` 或 `No` 的 `Final Answer:` 行

## 自测

<details><summary>Q1：如果模型输出里没有 `Action Input:`，只有 `Action: search`，你的 parse_react() 应该返回 action_input 为 None 还是空字符串？</summary>
None。因为 `Action Input:` 是独立字段，缺失即无值；空字符串容易和“输入为空”混淆（比如 `Action Input: ""`）。
</details>

<details><summary>Q2：为什么 temperature=0.0 很重要？试试改成 0.7 再跑，观察输出是否还守格式。</summary>
temperature=0.0 关闭随机性，强制模型严格遵循 prompt 格式。设为 0.7 后，它可能跳过 Action 直接写 Final Answer，或把 Action Input 写成自然句（如 “I’ll search for Shanghai…”），破坏解析。
</details>

<details><summary>Q3：Observation 是谁提供的？模型能自己生成 Observation 吗？</summary>
Observation 必须由你（代码）提供。模型从不生成 Observation —— 它只负责写 Action，你执行后把真实结果塞回去。如果模型自己编 Observation，就又回到“瞎猜”老路了。
</details>

## 下一章为什么是它

这一章你手动塞 Observation、手动拼 prompt、手动控制循环。  
但真实 Agent 要跑几十轮，不能每轮都 copy-paste。  
下一章《工具调用自动化》就来帮你：  
- 让模型声明它想用什么工具（不用你猜 Action 名）  
- 自动匹配函数、自动传参、自动把结果塞回去  
- 最终只要喂一句问题，它自己跑完全部 ReAct 步骤
