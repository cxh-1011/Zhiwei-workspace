# 第 3 章 上下文不是内存，是排队窗口

## 这一章要解决什么

你让模型帮你改一段 Python 脚本，它改得挺顺；过两轮你问“刚才那个 `df` 是不是应该加 `.copy()`”，它一脸懵：“哪个 `df`？”

不是它装傻。是它**根本没记住**——你聊了 10 分钟，它只记得最后排队进来的那截话。

这一章要把「上下文」这个词拆开：它不是大脑里的记忆，是**一个固定大小的窗口，只容得下最近几句话排队进来**。窗口满了，前面的就掉出去了。

就像地铁闸机——一次最多挤 5 个人，第 6 个来，第 1 个就被挤没了。它不是忘了你，是压根没看见你。

## 核心概念

### 上下文 = 输入 + 输出的总长度（单位：token）

你发一句“帮我修 bug”，它回“好的”，这算 2 句话，但 token 数可能有 20+。因为每个字、标点、空格、甚至换行符，都可能被切成独立 token。  
**为什么需要它？** 因为模型不认“句子”，只认 token 序列。你得知道窗口能塞多少 token，才知道能塞多少内容。

### 每个模型有硬上限（比如 32k、128k）

不是你家网络卡，是模型本身设计就只能看到这么多 token。超了直接报错 `context_length_exceeded`。  
**为什么需要它？** 你写 Agent 时如果把整个项目 README 都塞进去，很可能一发就崩——得提前切好、分批喂。

### tokenizer 是你的尺子，不是装饰品

`openai` 的 `tiktoken` 库就是干这个的：把文字按模型实际“看到”的方式切开、数清楚。  
**为什么需要它？** 光靠“字数”或“行数”估算会严重误判。中文里一个 emoji 可能占 4 个 token，而“的”和“地”在某些 tokenizer 里居然是同一个 token。

## 先跑起来

```python
import os
import tiktoken

# 确保环境变量已设：export OPENAI_API_KEY="sk-..."
client = openai.OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

# 用模型对应的 tokenizer（gpt-4-turbo 默认用 cl100k_base）
enc = tiktoken.get_encoding("cl100k_base")
text = "帮我看看这段代码有没有 bug：for i in range(10): print(i**2)"
tokens = enc.encode(text)
print(f"这句话共 {len(tokens)} 个 token")
print("前 5 个 token 对应的字：", [enc.decode_single_token_bytes(t) for t in tokens[:5]])
```

运行后你会看到类似：
```
这句话共 22 个 token
前 5 个 token 对应的字： [b'help', b' me', b' see', b' this', b' code']
```

注意：`decode_single_token_bytes` 返回的是字节，中文会显示成 `b'\xe4\xbb\xa3\xe7\xa0\x81'` —— 这正常，说明它真在按模型的方式切。

## 动手练

1. **算 token**：复制你微信里一段 200 字左右的技术聊天（比如讨论 pip 安装失败），用上面代码算出 token 数。✅ 做完标准：输出数字，比如 `共 317 个 token`。

2. **切对话**：找一段 1500 字的聊天记录（比如 GitHub issue 讨论 + 你和同事的回复），用 `enc.encode()` 算总 token；再手动切成前后两半，分别 encode，确认两半之和 ≈ 总数（允许 ±1，因切点可能在词中间）。✅ 做完标准：三个数字都打印出来，且后两者相加和第一个相差 ≤2。

3. **查上限**：访问 [OpenAI Models 页面](https://platform.openai.com/docs/models)，找到你正在用的模型（如 `gpt-4-turbo`），截图或抄下它的 “Context length”。✅ 做完标准：写出模型名 + 上限数字 + 单位（如 `gpt-4-turbo: 128,000 tokens`）。

## 自测

<details><summary>1. 我把一段 1000 字中文喂给 gpt-4-turbo，返回 context_length_exceeded。我改成只喂 500 字，还是报错。为什么？</summary>
可能你没算输出占用的 token。上下文上限是「输入 + 输出」总和。即使你只输 500 字，模型回复若很长（比如生成 200 行代码），也可能超限。
</details>

<details><summary>2. `tiktoken.encoding_for_model("gpt-4-turbo")` 和 `tiktoken.get_encoding("cl100k_base")` 返回一样吗？</summary>
一样。`gpt-4-turbo` 用的就是 `cl100k_base` 编码器。你可以 print 两个对象的 `name` 属性验证。
</details>

<details><summary>3. 下面哪句调用一定不会触发 context_length_exceeded？（假设 API key 有效）</summary>
A. `client.chat.completions.create(model="gpt-4-turbo", messages=[{"role":"user","content":"hi"}], max_tokens=1)`  
B. `client.chat.completions.create(model="gpt-4-turbo", messages=[{"role":"user","content":"a"*100000}], max_tokens=1)`  
C. `client.chat.completions.create(model="gpt-4-turbo", messages=[{"role":"user","content":"hi"}])`  
答案：A。B 明显超输入上限；C 不设 max_tokens，模型可能自己生成长回复导致总长超标；A 强制输出最多 1 token，输入又极短，总长必然安全。
</details>
