## 这一章的项目：把三次对比跑出来，存成四个文件

这一章的验收不看代码，看**四个输出文件**。正文「动手练」的三道题本来就要求
你把输出存下来，这里只把文件名固定住：

| 文件 | 里面放什么 |
|---|---|
| `output_temp0.txt` | `temperature=0.0` 跑 3 次的输出 |
| `output_temp08.txt` | `temperature=0.8` 跑 3 次的输出 |
| `no_system.txt` | 删掉 system 消息后跑 1 次的输出 |
| `truncated.txt` | `max_tokens=15` 跑 1 次的输出 |

三次输出之间用空行或 ``` 分开就行，不要求特定格式。

**验收会检查什么**

1. 四个文件都在，都不为空；
2. `output_temp0` 和 `output_temp08` 各有三段；
3. `temp08` 和 `temp0` 的内容**不完全一样**——temperature 调高之后，
   同样的输入不该再给出同一段字；
4. `no_system.txt` 里出现了「好的」「当然可以」「# 解释」这类说明性文字——
   这正是 system 消息在压制的东西；
5. `truncated.txt` 明显比 `output_temp0.txt` 短（不到 80%）——`max_tokens=15`
   会砍在句子中间。

**为什么盯这几个点**：模型接口的返回内容验收没法重放，但这四个文件的差异是
「参数确实改了」的物证。第 3 条最容易挂——把 0.0 的输出复制一份改名，
`temp08` 就和 `temp0` 一模一样了。

**如果接口不返回说明性文字**：换一个不带 system 的问题，或者用正文里那句
`# 解释：...` 作为对照。判分只看文件里有没有这类痕迹。
