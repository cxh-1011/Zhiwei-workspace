## 这一章的项目：把反馈归类、定优先级

正文「动手练」第 1、2 题。在 `main.py` 里写两个函数。

**一、归类**

```python
def classify_feedback(text: str) -> str:
    ...
```

返回四类之一：`"功能缺失"` / `"回答错误"` / `"太慢"` / `"其他"`。

判据（验收就按这个）：

| 类别 | 关键词 |
|---|---|
| 太慢 | 等、秒、卡、慢、延迟、转圈 |
| 回答错误 | 错、不对、胡说、答错、算错 |
| 功能缺失 | 能不能、希望、支持、加个、要是能 |

都没命中就是 `"其他"`。

**二、定优先级**

```python
def priority(repeat: bool, blocks_main: bool) -> str:
    ...
```

- 两个都真 → `"高"`；
- 只有一个 → `"中"`；
- 两个都假 → `"低"`。

`repeat` 是「多人重复提」，`blocks_main` 是「阻断主流程」。

**两个容易踩的点**

- 别写成 `if repeat or blocks_main: return "中"`：这样「低」永远不会出现，
  所有反馈都至少是「中」，排序等于没排。验收专门测了 `(False, False)`。
- 关键词要判在前面：「每次都要等 30 秒」里没有"错"字，但「等」很清楚；
  反过来「算是算对了，但太慢」同时含两类词，先判哪类得自己定一条规则，
  别让结果随 dict 顺序变。

**验收会检查什么**：七条真实语气的反馈都归对类（含一条"其他"）、
四组「重复 / 阻断」组合的优先级正确、两样都不占时是「低」。
