## 这一章的项目：把 messages 还原成「调了哪些工具」

正文「动手练」第 3 题。在 `main.py` 里写：

```python
def extract_steps(messages: list) -> list:
    ...
```

返回一个列表，每一步：

```python
{"tool": "get_weather", "args": {"city": "北京"}, "id": "call_1"}
```

- 只认 `role == "assistant"` 消息里的 `tool_calls`；
- 一条消息里有**两个** tool_call，就出两步；
- `role == "tool"` 的消息和普通对话都不算；
- `arguments` 是字符串时用 `json.loads` 解析，解析不了就把 `args` 设成 `None`，
  **不要让整个函数崩掉**。

**为什么值得单独写**

正文第 3 题让你手动补一条 `tool_calls` 历史再跑一轮，是为了看懂「模型第二轮
为什么这么答」。要看清这件事，得先能把这串 messages 读成「第几步调了谁、
参数是什么」。第 26 章的 trace 回放用的是同一个形状。

**两个容易踩的点**

- 别只取 `tool_calls[0]`：并行调用（一次查两个城市）在真实日志里到处都是。
- 解析失败要软着陆：日志里一定有被截断的 `arguments`，一个会抛异常的还原
  函数，等于在最需要它的时候不能用。

**验收会检查什么**：单次调用还原一步、一条消息里两个调用还原两步、
半截 JSON 时 `args` 为 `None` 且不抛异常、没有工具调用时返回空列表。
