## 这一章的项目：写一个规则版「选工具」

正文「动手练」第 1、2 题。在 `main.py` 里写：

```python
def choose_tool(query: str, tools: list) -> str | None:
    ...
```

`tools` 是 `[{"name": ..., "description": ...}]`，返回选中的工具名；
**没有一个合适就返回 `None`**。

验收用的四个工具：

| 工具 | 描述 |
|---|---|
| `check_syntax` | 检查 Python 文件的语法是否正确，只报告错误位置，不修改文件 |
| `edit_file` | 修改文件内容：调整缩进、替换文本、增删某几行 |
| `web_search` | 联网搜索最新信息，比如查某个库的最新版本号、官方文档更新 |
| `parse_python_code` | 分析 Python 代码结构，列出里面有哪些函数和类，不修改文件 |

**必须选对的五条请求**

| 请求 | 应该选 |
|---|---|
| 检查 config.py 语法是否正确 | `check_syntax` |
| 把 main.py 第 3 行缩进加 4 个空格 | `edit_file` |
| 查 pandas 最新版本号 | `web_search` |
| 这段代码里有哪些函数？只看结构，别改 | `parse_python_code` |
| 给 utils.py 里的 return 换成 yield | `edit_file` |

外加一条「今天星期几？」必须是 `None`。

**两个容易踩的点**

- 「这段代码里有哪些函数」这条最容易判给 `check_syntax`——它也在"看代码"。
  区分点在于「结构」而不是「语法」。
- 返回 `None` 不等于失败：真实场景里这对应「模型直接回答，不调工具」，
  硬选一个反而会白花一次调用、甚至改错文件。

**验收会检查什么**：五条请求各选对、返回值必须是工具列表里存在的名字
（不许瞎编）、无关请求返回 `None`。第 3 题（10 个请求测召回率）要调模型，
不在这里验。
