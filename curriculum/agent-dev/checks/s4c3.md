## 这一章的项目：三道锁合一个判断

正文「动手练」第 1、3 题。在 `main.py` 里写：

```python
def check_budget(tokens_used, seconds_used, turns_used,
                 max_tokens=2000, max_seconds=30, max_turns=3):
    ...
```

- 没超任何一项 → 返回 `None`；
- 超了 → 返回 `"token"` / `"time"` / `"turns"` 之一；
- **三个都超时按 token → time → turns 的顺序报**。

**为什么优先级是这个顺序**

不是随便定的。token 超了接口会直接报错，钱已经花出去了；时间超了用户已经
在等；轮次超了只是「该换个问法」。先报损失最大的那个，日志里才不会写着
"轮到上限了"而掩盖掉真正的 token 爆炸。

**接入循环**

```python
for turn in range(max_turns):
    reply = ask(messages)
    used["tokens"] += reply.usage.total_tokens
    used["turns"] += 1
    reason = check_budget(used["tokens"], time.time() - started, used["turns"])
    if reason:
        print("停止：", reason)
        break
```

**两个容易踩的点**

- 用 `>` 还是 `>=`：`max_tokens=2000` 的意思是「最多 2000」，用到 2000
  就该停。验收按 `>=` 判。
- 上限别写死：`max_tokens` 是参数。换一个便宜模型，2000 这个数字就不合适了。

**验收会检查什么**：八种用量组合（含边界 2000 / 30 秒 / 3 轮、三项同时超）；
`max_tokens` 改成 400 时 500 个 token 要报；改成 10000 时不报；刚开跑返回 `None`。
第 2 题的 `timeout=0.1` 要真发请求，不在这里验。
