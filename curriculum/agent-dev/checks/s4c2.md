## 这一章的项目：判断这一轮该不该停

正文「动手练」第 2 题。在 `main.py` 里写：

```python
def should_stop(text: str) -> bool:
    ...
```

看到这三个信号之一就返回 `True`：

- `查不到就放弃`
- `已拿到答案`
- `Final Answer:`（大小写不敏感）

其他一律 `False`。

**为什么这是个单独的关卡**

正文第 2 题的写法是：

```python
if "查不到就放弃" in content or "已拿到答案" in content:
    break
```

终止检测写错有两种后果，都很难查：

- **太松**：认了「答案已经拿到了」这半句 → 提前退出，用户拿到半截答案；
- **太严**：模型说了「查不到就放弃」你却没认出来 → 转圈直到轮次上限。

所以验收里专门放了一条「答案已经拿到了，但我要再确认一下」——它含「答案」
三个字，但**不是**终止信号。

**两个容易踩的点**

- 别用 `"答案" in text`：上面那条会被误停。要匹配完整的 `"已拿到答案"`。
- 别忘 `lower()`：模型常写 `Final Answer:` 和 `final answer:` 两种。

**验收会检查什么**：四个该停的（含多行、带 Thought 前缀的）都停，
四个不该停的（含上面那条陷阱）都不停，返回值是布尔。
