## 这一章的项目：交接时别把限定条件丢了

正文「动手练」第 2 题。在 `main.py` 里写：

```python
def check_handoff(a_resp: str, b_instruction: str):
    ...
```

- `a_resp` 是 Agent A 的回答；
- `b_instruction` 是交给 Agent B 的指令；
- A 的回答里出现了温度（`℃` 或 `摄氏度`），但 B 的指令里**没提单位**，
  就返回一句含「单位」的警告；
- 其余情况返回 `None`。

**返回值长这样**

```python
"⚠️ B 指令未覆盖单位，可能丢失精度"
```

**这道题在讲什么**

A 算出「32℃」，B 只收到「润色一下」，润完变成「32 度左右，挺热的」——
单位没了，下游当成华氏度用，整条链路错得很自然。正文用「耗时日志」「冲突提示」
「发起方标记」三道工序来防这类问题，这一题是其中最好写成代码的一道。

**两个容易踩的点**

- 没问题时必须返回 `None`，不要返回 `""`：`if warning:` 对空串是假，
  但 `if warning is not None:` 就误判了。统一用 `None` 表示"没问题"。
- 判断 B 的指令要宽松些：`保留单位`、`别丢摄氏度` 都算提到了。

**验收会检查什么**：五组交接（含「摄氏度」写法、指令里已提单位、A 没有具体温度、
空回答）判断正确；没问题时确实是 `None`。

第 1 题（加耗时日志）和第 3 题（改 role）要真跑两个 Agent，不在这里验。
