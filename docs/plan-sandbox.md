# 第四优先：学习项目沙箱（v0.24.0）

> 目标：让 agent 在磁盘上真的建一个目录，在里面陪学生写代码、跑起来、验收到没到位。
> 不是「让助手改我的仓库」，而是「给这门课的每一章一个能动手的空地」。
>
> 范围：项目创建与登记、沙箱切根、验收执行器、学习模式的权限边界、项目级 venv、
> 清单变更后的自动重装、断网表现、学生用 JS 写代码时的验收。
> **不含** Go / Deno / npm（见第 9 节末）。

## 0. 三个必须先修掉的坑

这三条是动手前就写在规划里的，实际做的时候全都撞上了：

1. **`_guard.WORKSPACE_ROOT` 是导入时读一次的常量。**
   `workspace.py` / `repo.py` / `desktop.py` 都是 `from ._guard import WORKSPACE_ROOT`，
   拿到的是**值拷贝**。想「临时换个根」只能改进程全局变量，而且三个模块各拿一份
   旧值——改了一处，另外两处还指着旧目录。
   改成：基础根（`WORKSPACE_ROOT`，仍是常量、仍可被测试覆盖）+ 运行时登记的
   额外根（`register_root`）+ 当前活动根（contextvar，`use_root` 切换）。
   不给 `resolve()` 加 `root` 参数，是因为它有十几处调用点，漏改一处的后果是
   **静默回落到仓库根**——学生在项目里写文件，文件落到了仓库里，还不报错。

2. **没有独立的「建项目」。**
   唯一的写入能力是 `write_file`，它要求目标文件的父目录已存在，
   于是「从零开始」这件事在工具层就做不到：总得先有人在资源管理器里建个文件夹。
   补 `projects.create()`：建目录、写 README/.gitignore、登记成根，一步到位。

3. **没有验收执行器。**
   学完一章没人能回答「我写对了吗」。补 `checks/<chapter>.py` + `backend/checks.py`：
   子进程跑、带超时、整棵进程树清理、收回结构化结果。
   没有脚本的章如实返回「这章没有自动验收」，绝不假装通过。

## 1. 两种根，不要混

| | 基础根 `base_root()` | 活动根 `active_root()` |
|---|---|---|
| 是什么 | 代码仓库本身 | 这次工具调用能碰到的目录 |
| 谁用 | 备份目录、桌面截图、`projects/` 的父目录 | `resolve()`、`rel_inside()`、git 的 cwd |
| 会变吗 | 不会（测试里可以改） | 每次进/出项目变一次 |

`edits.py` 的备份固定写基础根：项目目录里凭空多个 `backups/` 会污染学生的项目，
而且他一删就等于删掉了回滚点。这条区分是刻意留的，不是漏改。

## 2. 切根只有一个入口

```python
with projects.sandbox(project_id) as project:   # 进项目
    ...                                        # 活动根 = 项目目录
# 退出自动还原
```

`sandbox()` 做三件事：校验项目存在、`register_root` + `use_root`、`finally` 还原。
`use_root()` 拒绝未登记的目录——否则「切根」就等于「任意目录可读写」。

流式对话里，切根必须发生在**流内部**：

```python
def event_stream():
    with projects.sandbox(message.project_id):   # 对
        for event in run_agent_stream(...): ...
```

包住 `return StreamingResponse(...)` 是错的：响应对象构造完就退出了 `with`，
真正迭代时活动根已经还原。页面看起来正常，但工具全都作用在仓库根上——
这是最坏的一种失败，没有任何报错。

## 3. 项目目录

```
projects/<course_id>/<slug>/     # slug 从项目名转，转不出就用章节号
├── README.md                    # 章节任务 + 函数契约 + 怎么自测
├── .gitignore                   # __pycache__ / *.pyc / .venv
└── ...                          # 学生和 agent 写的代码
```

- 名字限制 40 字；`slugify` 只留 `[a-z0-9-]`，中文名转不出就用章节 id 兜底，
  重名自动加 `-2`、`-3`。
- 每章最多 20 个项目，防止「每次跑都新建一个」。
- **不提供删除目录**。`DELETE /projects/{id}` 只删数据库行，磁盘目录保留，
  列表里如实标成「目录不在了」。删文件是不可逆的，而这个功能的用户是刚开始
  写代码的人；把「清理列表」和「删掉我写了三小时的项目」合成一个按钮，
  早晚会有人手滑。
- `projects/` 在 `_guard.BLOCKED_DIRS` 里：从仓库根看过去整棵不可见，
  所以打开 A 项目时读不到 B 项目。切进项目后相对路径里没有这一层，不影响内部读写。

## 4. 验收脚本的契约

`curriculum/<course>/checks/<chapter>.py`，用 `python <script> <项目绝对路径>` 跑，
cwd 就是项目目录。**最后一行**输出：

```json
{"items": [{"name": "基本样例能拆出三个字段", "ok": true, "detail": ""}]}
```

`passed` / `total` 由执行器数——让脚本自己算就会算错。六个决定：

1. **独立进程**。学生代码会崩、会死循环、会 `sys.exit()`。同进程 import 一次
   `while True` 就把后端拖死，而且没法超时。
2. **同一个解释器**（`envs.python_for()`）。项目有 `.venv` 用它，没有才落回
   `sys.executable`。两边不同会踩到两种假失败：「学生用 3.11 写的语法，验收跑在
   3.8 上」和「明明 `pip install` 了，验收却 import 不到」。见第 7 节。
3. **超时杀整棵进程树**。学生项目里 `subprocess.Popen` 起个服务是常见写法，
   只杀父进程会留下孤儿占着端口，下一次验收直接「地址已被占用」。
4. **容忍 stdout 噪音，只认最后一行 JSON**。学生代码里一句 `print("debug")` 是常态，
   要求「只能输出 JSON」等于让第一次验收必然失败；但也只在最后 40 行里找，
   不会把日志里随便一个 `{}` 当结果。
5. **退出码不重要**。非 0 但输出了合法 JSON 也算跑成功——「验收不通过」本身就
   该用非 0 退出码表达。
6. **零条检查不算通过**。脚本坏了、什么都没跑，是最该被看见的失败。

`_kit.py` 提供 `run(project, cases)`：按 `main.py` → `solution.py` → `app.py` 找模块，
用 spec 从文件加载（不走 `sys.path`，避免撞上同名包或旧缓存），每项单独 try。
一个 `.py` 都没有、只有 `main.js` 时，同一个 `run()` 会把 JS 模块包成一样的对象
（见第 9 节）——所以「加一章」仍然是加两个文件，和语言无关。
失败信息只取 traceback 最后一行：倒数第二行是 `raise ...` 的源码，对刚学写代码的
人满屏都是噪音，真正有用的是「parse_react 返回了 list，应该返回字典」。

## 5. 学习模式的权限：有项目才有写和运行

```python
sandbox = bool(project_id)
if mode == "tutor":
    allow_code_edit = sandbox
    allow_command = sandbox
    allow_workspace = False
```

这条写在 `agent.py` 而不是接口里：接口有两个（`/chat` 与 `/chat/stream`），
以后再加第三个时不必记得抄一遍。两个方向都要挡：

- **有项目**：读写工具 + `run_command` 全部挂上，不用用户勾选——学习场景本来就该
  边写边跑；但根是项目目录，仓库整个不可见。
- **没项目**：即使请求里把 `allow_code_edit`、`allow_command` 都打开，也不给文件工具。
  否则导师能读到 `curriculum/` 里的题库和答案。

审批链没有被放松：`python -c` 仍是 ask 级、删除类仍是 deny。自动放行的只有
`python xxx.py` 这种白名单命令——学生项目跑起来靠的就是它。`pip install` 仍是
ask 级；在沙箱里它会被解析到项目 venv 的 pip，不会装进后端那个 Python。

## 6. 33 章都有验收了

每章一个 `checks/<章>.py` + `checks/<章>.md`。脚本只做两件事之一：

- **验函数**：正文「动手练」里最容易落成代码的那道题（很多章正文直接给了
  函数名，比如 `parse_react`、`resume_after_approval`、`replay_trace`）；
- **验产物文件**：那一道题的输出（`tool_call.json`、`memories.jsonl`、
  `agent_limits.md`……）。

| 章群 | 验的落点 |
|---|---|
| 1 模型原理 s1c1–s1c3 | 中英 token 对比；四份参数对比输出；切两半数 token + 上下文上限记录 |
| 2 提示词 s2c1–s2c3 | 四段式拼装与缺段判断；示例干净度；JSON 提取 + 字段校验 |
| 3 工具调用 s3c1–s3c4 | `tool_call.json`；`parameters` 补全；参数解析校验；规则版选工具 |
| 4 ReAct s4c1–s4c4 | `parse_react`；终止判断；三道护栏；messages 链路还原 |
| 5 记忆 s5c1–s5c3 | `trim_conversation`；jsonl 记忆读写；`bad_memory_example.md` |
| 6 RAG s6c1–s6c4 | 切句 + 完整性；余弦与排序；阈值 top-k + `reranked_chunks.json`；编造检测 |
| 7 流式/中断/审批/日志 s7c1–s7c4 | 逐块转发；取消清临时文件；审批与恢复；trace 回放 |
| 8 评测 s8c1–s8c3 | 失败抽题 + `test_cases.json`；`price_check`；新旧结果对比 + 三份回归产物 |
| 9 多 Agent s9c1–s9c3 | 选型意见；交接冲突检测；`agent_limits.md` 三条红灯 |
| 10 成本与迭代 s10c1–s10c2 | 成本计算与双模型对比；反馈分类与优先级 |

**纯讨论章（s1c2、s5c3、s9c1、s9c3）没有代码产物**，脚本验的是正文明确要求
的那份文件（四个输出 txt / 坏记忆示例 / 选型笔记 / 红灯清单），检查项都落在
「正文说了必须有的东西」上，不额外加要求。

加一章 = 写 `checks/<chapter>.py` + `checks/<chapter>.md`（任务说明，会进 README），
不用改后端。`checks.list_chapters()` 自动发现，前端据此决定显不显示「跑验收」。

`.md` 同时会在项目卡里就地展开（`GET /projects?chapter_id=` 返回章级 `brief`）：
学生建项目之前就能看到这一章要交什么，不用先翻 README。

## 7. 项目级环境（venv）

### 为什么原来不做，现在又做了

原来两条理由：建 venv 要十几秒；验收和「学生自己跑」会用两个不同的 Python。
第一条靠「不自动建」解决；第二条反过来正是要做的理由——学生 `pip install`
之后验收看不见那个包，「明明装了却 import 不到」对刚学写代码的人几乎无法
自己诊断。工具端必须消掉这类失败。

### 三条边界

1. **不自动建**。建项目时建会让「新建」卡十几秒，跑验收时建会让每次验收都卡。
   只有用户点「准备环境」，或者他要装依赖时才建。33 章验收只用标准库，
   多数项目根本不需要这一步。
2. **装了就用**。`.venv` 存在 → 验收脚本、`run_command` 的 `python`/`pip`/`pytest`
   全用它；不存在 → 落回跑后端的解释器，行为和加这个功能之前完全一样。
   解释器只有一个出口：`envs.python_for()`。调用方不要自己拼 `sys.executable`。
3. **requirements.txt 不是脚本**。pip 的 `-e .`、`git+https://…`、`--index-url`
   都能执行任意代码或指向任意源，所以只放行「包名 + 版本约束」：拒绝 `-` 开头、
   URL、本地路径、环境标记、shell 符号、含空格的行，最多 30 行、每行 120 字符。
   要装别的地方来的东西，让学生自己在终端里做。

### 为什么不给 agent 一个「装依赖」工具

模型能写 `requirements.txt`，装不装、什么时候装由用户点按钮决定。给它一个
自己联网装包的工具，等于让一次对话能改变机器上的软件状态，而且事后无法回答
「这个包是谁装的、装到哪个解释器里了」。`run_command` 里 `pip install` 仍是
ask 级（要用户确认），且会被解析到项目 venv 的 pip。

### 真实验证过的数字（本机）

| 步骤 | 耗时 |
|---|---|
| `python -m venv`（带 pip） | 15.9 s |
| `pip install requests`（有缓存） | 25.1 s |
| venv 里 `import requests` | 0.1 s，版本 2.34.2 |

`.venv` 在 `.gitignore` 里、`tree()` 排除、`_guard` 的 `BLOCKED_DIRS` 也挡掉——
学生不会在项目文件列表里看到几千个依赖文件。

## 8. 清单改了就自动重装

### 装过什么记在哪

`<项目>/.venv/.zhiwei-env.json`，不记数据库。它是环境的附属物：`.venv` 被
谁删掉，记录跟着一起消失，永远不会出现「库里说装好了、实际没有」。记录里
两份指纹：`hash` 是**装成功**的那份清单，`attempted_hash` 是**上次试过**的那份，
外加 `error` 与 `error_kind`。

### 七种状态，前端各有一句话

| state | 含义 | 页面 |
|---|---|---|
| `none` | 没有清单或里头没包 | 不显示 |
| `invalid` | 清单不合法 | 「requirements.txt 有问题」+ 悬停看第几行 |
| `no_env` | 有清单没环境 | 只显示「准备环境」 |
| `unrecorded` | 有环境有清单、没有安装记录 | 「装依赖 N」 |
| `changed` | 清单和装过的不一样 | 「更新依赖 +1」 |
| `failed` | 这份清单上次失败了 | 「依赖装失败」+「重试装依赖」 |
| `ok` | 装的就是这份 | 「依赖已装 N」 |

### 谁来触发

`POST /projects/{id}/check` 里先 `envs.sync()` 再跑验收。放这里的理由：学生
改完 `requirements.txt` 的下一步就是点「跑验收」，那时看到 `ModuleNotFoundError`
是最没用的信息——他明明写了依赖。装失败不拦验收，`deps` 字段随结果返回，
页面写一句「下面的结果可能缺包」。

`unrecorded` 也算要装：可能是学生自己在终端 `pip install` 过，我们无从判断，
装一次（pip 对已满足的包是秒过的）就有记录了。

**失败不自动重试**。断网时每次验收都撞一次网络，会把「点一次等十几秒」变成
常态。同一份清单失败过就停在 `failed`，只在页面提示，重试要人点。清单再改
（指纹变了）才重新允许自动试一次。

### 断网和包名拼错必须分开说

pip 在两种情况下给的是**同一句** `ERROR: No matching distribution found`，
只有前面那几行 `WARNING: Retrying ... NewConnectionError` 能分开。所以
`failure_kind()` 先看连接类标记，再看「找不到包」：

- `offline` →「连不上 PyPI —— 装依赖要联网，这次的包没装进去。已经装过的包
  不受影响；网络恢复后点「重试装依赖」。」；
- `missing` →「PyPI 上找不到这个包（名字拼错，或者没有这个版本）」；
- 其他 → 退出码 + pip 原话。

不这么分的话，断网会被报成「你包名拼错了」，学生照着改包名只会更糊涂。
另外 pip 自己的重试是 5 次 × 15 秒，断网能拖几分钟；这里固定
`--retries 1 --timeout 15`，本机实测断网 **6.0 秒**失败。

### 顺带清掉 pip 的临时目录

pip 被超时杀掉时会在项目根下留 `pip-build-tracker-*`、`pip-install-*`、
`pip-ephem-wheel-cache-*`，而 `tree()` 会把它们当成学生的文件。`install()`
在 finally 里按前缀清掉，只删这三类目录。

## 9. 多语言：学生可以用 JS 写

### 为什么这么接

33 章的验收脚本都是「拿到函数 → 喂数据 → 看结果」。所以只需把 JS 模块包成
**长得像 Python 模块**的对象（`_kit.JsModule`）：取属性得到可调用对象，调用时
起一个 node 进程，参数 JSON 过去、返回值 JSON 回来。**33 章检查代码一行没改**。

反过来做（给每章写一份 JS 版检查）意味着 66 个文件要同步维护，且两份契约
迟早对不上。

### 语言怎么判断

看项目根目录：有 `.py` 就算 Python，一个 `.py` 都没有而有 `.js/.mjs/.cjs`
才算 JS。混着放时 Python 优先——33 章正文示例都是 Python，他要交的那份也是；
反过来按 JS 验会把写对的作业判成「没交」。只看根目录：扫全量会把 `.venv`
里几十万个 `.py` 数进来，那条判断永远成立、等于没判断。

### 三章只能 Python

`s1c3`（要传 `encode` 函数）、`s6c2`（要传 `embed` 函数）、`s7c1`（要传 `sink`
回调，还有生成器参数）——回调跨语言传不过去。这三章在 `run(..., languages=("python",))`
里声明，学生交 JS 时得到的是「这一章的验收只支持 Python：它要把一个 Python
函数当参数传进你的代码」，而不是一句 `Object is not JSON serializable`。

### 几个必须做对的细节

- **进来先加载一次**（`JsModule._load`）：语法错误、没装 node 这类失败只有
  在加载时拦下，才会显示成第一条「你的 JS 文件加载失败：…」，而不是摊成
  每条检查都「抛了同一个错」。
- **导出名同时认 `parse_react` 和 `parseReact`**：验收要求是 snake_case（全课程
  统一），JS 习惯是 camelCase。名字不该成为「写对了却判不过」的原因。
- **异常要带上原话**：检查里原来只写 `type(exc).__name__`，JS 抛的错会变成
  「抛了 Missing」。21 处统一改成 `why(exc)`，输出 `Missing: 你的 JS 里没有导出
  extract_json。现在导出的是：…`——JS 那边的话是他唯一能改的线索。
- **JS 项目不碰 pip**：`/check` 只在语言是 python 时才 `sync()`，页面上也不显示
  「准备环境 / 装依赖」，只标一个「JS 项目」。验收入口标题写「· Node 22.22.2」。

### 不做的

Go 要编译（产物放哪、增量怎么算），Deno 要额外拉运行时，`npm install` 也要
决定装到哪、要不要 `.gitignore`。这些都不是「加两个文件」的量级，所以只把
一门做完整。要加的时候：`runtimes.RULES` 加一条、`student_language` 加一个
扩展名，执行器和 `_kit` 自动跟着变。

## 10. 刻意不做的

- **需要联网或第三方包的那道题**：`tiktoken`、`sentence-transformers`、真调模型
  的题一律不进验收。文字说明里写清"这题不在此检查"，不假装验过。
