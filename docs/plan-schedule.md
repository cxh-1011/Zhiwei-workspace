# 第三优先：学习排期器（v0.23.0）

> 目标：把「33 章要学」变成「今天学第 11、12 章，明天学第 13、14 章」。
> 输入是课程依赖 + 能力画像 + 用户能投入的时间，输出是具体日期上的槽位。
>
> 范围：排期、重排、按天落地。**不含**日历订阅、提醒推送、跨课程统筹。

## 0. 三条必须先定的边界

1. **日期和分钟由代码算，模型最多决定「先动哪几章」。**
   模型不知道今天周几、不知道用户昨天已经掉队，让它排日程必然给出
   「周三学两小时」这种执行不了的安排。它只在「同时能选的几章里」给偏好，
   而且还要过一遍依赖检查（`safe_order`）：把第 20 章排到第一天，等于
   让用户点开就撞一堵墙。

2. **排期只排「未来」，不存「完成」。**
   学完一章由 `course_progress` 表达。排期表再存一份「这个槽完成了」就是
   两套真相，撤销时必然对不上。排期页的「标记学完」直接调
   `PATCH /course/progress`，和章节页是同一个接口。

3. **诊断判过的段不占时间，但不算「学完了」。**
   `course.satisfied_ids()` 已经把「学完的」和「诊断判会且前置满足的」
   合成一个集合；排期用这个集合做过滤。诊断只影响「排不排」，
   不动进度条、不动 `course_progress`——这是画像落地时定下的规矩。

## 1. 表

```sql
CREATE TABLE plan_settings(
    course_id TEXT PRIMARY KEY,
    start_date TEXT NOT NULL,
    weekdays TEXT NOT NULL DEFAULT '1,2,3,4,5,6,7',  -- 1=周一
    minutes INTEGER NOT NULL DEFAULT 60,
    include_skipped INTEGER NOT NULL DEFAULT 0,
    catch_up TEXT NOT NULL DEFAULT 'shift',
    basis_sig TEXT DEFAULT '',   -- 排这份计划时的画像签名
    updated_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE plan_slots(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    course_id TEXT NOT NULL,
    day TEXT NOT NULL,           -- YYYY-MM-DD，本地日期
    seq INTEGER NOT NULL DEFAULT 0,
    chapter_id TEXT NOT NULL,
    minutes INTEGER NOT NULL DEFAULT 0,  -- 排下去那一刻的快照
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

两个刻意的设计：

- **`minutes` 是快照，不跟着课程改。** 以后把某章从 40 分钟调成 60 分钟，
  不该让已经排好的今天凭空多出 20 分钟。要改就重排。
- **`basis_sig` 只记「哪些阶段被判可跳过」。** 等级从 2 变 3、依据文字变了，
  不改变要排哪些章，不必提示重排。诊断重测会改签名，页面据此提示
  「该重排了」——只提示，不自动重排，自动改日子等于替用户决定哪天学什么。

## 2. 算法

### 2.1 分类（`schedule.classify`）

33 章分成四堆：

| 堆 | 判据 | 是否排 |
|---|---|---|
| done | `status == 'done'` | 不排 |
| skipped | 在 `satisfied_ids` 里但没 done（诊断判会 + 前置传导） | 不排（除非勾了复习） |
| unwritten | 正文文件不存在 | 不排 |
| learnable | 其余 | 排 |

`satisfied_ids` 是不动点迭代出来的：某段被判 2 级但前置没学，那几章不算
满足，必须排进去。否则排期会从第 15 章开始，而第 10 章压根没读过。

勾了 `include_skipped` 时，skipped 的章也进 learnable（复习），但依据里
不再把它们算成「省下的时间」。

### 2.2 铺日期（`schedule.assign`）

- 按顺序拿章，当天剩余容量放得下就放，放不下换下一个可用日；
- **一章不拆**：半章没法验收，也没法说「今天学了半章」；
- 单章比一整天还长（90 分钟章 / 每天 60 分钟）时独占一天，宁可那天超一点；
- 默认每天 90 分钟：课程一章 40 分钟，90 分钟正好两章，不浪费整天。

### 2.3 依赖安全顺序（`schedule.safe_order`）

模型给的 `order` 先过一遍：每放一章都检查前置是否已在 satisfied 或已排。
不满足就推迟，最后按原顺序收尾。模型漏掉的章自动补在后面。
**模型只能改变「同时可选的章」的先后，不能改变「能不能现在学」。**

### 2.4 掉队三策略（`schedule.reschedule`）

| 策略 | 对「过期没学」的态度 | 实现 |
|---|---|---|
| `shift` 顺延（默认） | 都学，结束日往后推 | 从今天起按原每日容量重排全部未完成章 |
| `compress` 压缩 | 都学，结束日尽量不动 | 每日容量提到「在原结束日前排完所需」，上限 240 分钟 |
| `drop` 放弃 | 本轮不排这几章 | 过期的未完成章丢弃，其余从今天重排；章仍留在课程里 |

三种是三种态度，不合成一个「智能调整」。合成之后用户说不清
「为什么这章被跳过了」。

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/plan` | 设置、槽位、按天分组、统计、依据、`stale` |
| POST | `/plan/build` | 按当前画像整份重排；参数可只传改动项 |
| POST | `/plan/reschedule` | 掉队重排，`strategy = shift / compress / drop` |
| DELETE | `/plan` | 清空排期与设置，不动任何学习记录 |

`GET /plan` 的 `basis` 不依赖槽位：还没排期时也能说清
「33 章里 10 章按摸底跳过、省下 400 分钟」，否则用户不知道为什么
这门课忽然只剩 23 章。

`POST /plan/build` 的 `use_model=true` 才会调模型；默认关——没配模型时
点一下要等超时，比不给这个按钮更糟。模型失败自动回退课程顺序，
响应里的 `order_source` 会如实写 `default`。

## 4. 前端

- 目录底部第三张卡：没排期显示「N 章待学 · X 小时」+「排一份」；
  排过显示「预计 12/12 收尾 · 今天 2 章」。
- `#plan` 独立视图：设置区（开始日 / 每周哪几天 / 每天分钟 / 复习开关）、
  按天分组、每章「去学」和「标记学完」、掉队提示条、清空。
- 画像变了但没重排：页面顶部一条冷色提示 +「按新画像重排」按钮，
  说明文字改成「这份排期是按上次画像排的」，不再把新旧口径混在一句里。
- 诊断交卷后会重拉课程树：目录的「跳过」标签、排期的依据都跟着变。

## 5. 验证

- `test_schedule.py` 99 项：设置边界、分类、依据、铺日期、依赖安全顺序、
  模型 JSON 解析、三种掉队策略、统计、接口鉴权与画像联动、`stale`。
- 关键断言：
  - 诊断判 s1–s3（10 章）后，排期从 33 章降到 23 章、省 400 分钟、
    第一课是第 11 章；
  - 学完一章重建后那章不再排；
  - 顺延不丢章、压缩不丢章、放弃只丢过期没学的章；
  - 模型把第 33 章排第一时，依赖检查仍让它留在最后。
- 真浏览器 `backups/ui_smoke/probe_plan.py` 20 项：排期、改分钟重排、
  标记学完、画像变化提示、按新画像重排、刷新后仍在。

## 6. 已知取舍

- **一次排完整门课，不是只排一周。** 界面按天展示，用户可以自己看本周；
  只排一周会让「预计什么时候学完」永远算不出来。
- **掉队检测按「日期 < 今天且未学完」算，不按连续天数。** 周一周二没学、
  周三学了，周二那章仍算过期——它确实没完成。
- **`drop` 放弃的章不会自动回来。** 下次重排（`/plan/build`）会把它们
  重新纳入，因为课程里它们仍然没学完。这是有意的：放弃的是「本轮」。
- **不做日历提醒。** 排期是「打开学习台时看到今天干什么」，不是推送系统。
